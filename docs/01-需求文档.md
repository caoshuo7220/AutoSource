# 数据源自动发现能力建设需求文档

## 一、项目背景

当前上游数据源依赖人工梳理提名，存在覆盖度低、体系性弱、人力成本高的问题，受限于个人视野难以实现行业级全域覆盖。为快速扩充数据源规模、构建体系化数据源池，启动 AI 驱动的上游数据源自动发现能力建设。

## 二、项目目标

### 核心目标

输入粗粒度领域描述，自动产出结构化、可量化的数据源清单，替代人工梳理模式，大幅提升数据源产出效率与覆盖广度。

### 阶段目标

1. **试点期**：在熟悉领域完成方案验证，实现单领域批量数据源输出，确认链路可行性。
2. **优化期**：解决单轮输出覆盖不足问题，实现扩量生成，提升分类合理性与输出规模。
3. **落地期**：输出标准化元数据，完成与下游采集链路的对接。

## 三、功能需求

### 3.1 领域输入

系统接收领域描述文本，作为自动发现的范围边界。输入为必填项，同时支持以下可选约束：

- **领域描述**（必填）：粗粒度文本，如"算力服务器"，作为发现范围边界。
- **分类路径**（可选）：用户可预先指定分类层级结构；若提供，系统直接使用该结构进行数据源发现，跳过自动拆解。若未提供，系统自动完成领域拆解。
- **数据源类型**（可选）：用户可限定目标数据源的内容体裁类型（如仅"数据集"、"专利论文"、"产品文档"）；若提供，系统仅产出匹配类型的数据源。若未提供，系统自动按实际形态标注。

- 支持中文或英文输入。
- 无需预定义分类体系，边界由输入内容自然界定。

### 3.2 领域拆解

当用户未提供分类路径时，系统自动对输入领域做层级化细分，形成树状分类结构，作为后续数据源发现的搜索骨架。若用户已提供分类路径，则跳过此步骤。

拆解需遵循以下原则：

- **层级清晰**：各级分类之间为严格的包含关系，上一级完全包含下一级；同级分类之间互斥不重叠。
- **符合领域常识**：分类体系应与该领域公认的知识体系一致，拆分维度和命名方式符合行业习惯（如"医疗影像"按成像模态拆分，而非按文件格式拆分）。
- **符合业务使用逻辑**：分类粒度应匹配下游数据使用的实际场景，避免过细造成冗余或过粗造成检索困难。
- **深度自适应**：拆解深度由模型根据领域实际情况动态决定，不同领域的层级深度可不同（如"金融"可能拆为 4 层，而"开源框架"可能只需 2 层）。
- **覆盖完整**：拆解结果需覆盖该领域的主要方向，无明显遗漏。

### 3.3 数据源发现

基于领域拆解结果，逐节点进行网上搜索，挖掘对应的公开数据源。

- 每个细分方向应构造合适的搜索策略，确保覆盖中英文公开资源。
- 发现的每个数据源需关联到对应的分类路径节点。

**扩量生成机制：**

- 触发条件：以下任一条件满足时触发扩量——（1）任一分类节点下产出数据源数量相对于同领域其他节点显著偏少或为空；（2）全量产出中各分类节点覆盖不均。
- 扩量方式：对覆盖薄弱的节点调整搜索关键词（如变换中英文表述、添加近义词、扩大搜索范围）后重新搜索。
- 终止条件：各分类节点均有足够代表性条目（有足够数量和多样性以代表该子方向的公开数据源生态），且继续扩量不再显著增加新的有效条目（新增率收敛）。不设固定数量阈值，避免因领域规模差异导致过早停止或过度生成。

**搜索无结果降级策略：**

- 若某个分类节点首次搜索无结果，应尝试更换搜索关键词（至少 2 次不同表述）重新搜索。
- 若更换关键词后仍无结果，该节点标记为"无数据源"并在输出结果中注明，不阻塞整体流程。
- 若所有分类节点均无结果，系统返回空清单并在输出中说明各节点搜索尝试情况，同时给出建议（如调整领域描述、扩大搜索范围）。

### 3.4 分类标签挂载

为每条数据源自动挂载分类路径标签，形成树状分类体系。

- 分类路径格式：以 `-` 分隔的层级路径，层级深度由模型根据领域实际结构决定，示例：`计算机科学-计算机视觉-人脸识别`。
- 分类路径需层级清晰、语义统一，符合领域常识。
- 同一数据源不可同时出现在多条分类路径下。

### 3.5 结果输出

将数据源清单以结构化格式输出。

- 输出需包含每条数据源的完整元数据字段（见输出规范章节）。
- 最终输出格式为 CSV 文件（UTF-8 BOM 编码，兼容 Excel 直接打开）。
- 输出结果应经过去重处理：以 URL 域名 + 数据源名称为联合去重键，二者均相同视为重复。同一数据集若存在于多个镜像站（URL 域名不同），各镜像站作为独立条目保留。

## 四、输出规范

每条数据源需包含以下必填字段：

| 字段名 | 类型 | 说明 | 示例 |
|--------|------|------|------|
| 数据源名称 | 字符串 | 数据源官方标准名称，不可为空 | NIH Chest X-ray Dataset |
| 分类路径 | 字符串 | 以 `-` 分隔的层级分类路径，深度由领域实际结构决定 | 医疗影像-X光影像-胸部X光数据集 |
| 数据源类型 | 字符串 | 数据源的内容体裁，由模型根据数据源实际形态确定，不做全局枚举限定。常见类型包括但不限于：技术博客、产品文档、专业书籍、专利论文、开源仓库、数据集、排行榜/基准、行业标准、资讯平台等 | 数据集 |
| 访问地址 | URL 字符串 | 数据源主入口 URL，不可为空 | https://www.nih.gov/... |
| 简要说明 | 字符串 | 1-2 句话说明数据源内容与核心价值 | 包含 10 万+ 胸部 X 光图像及对应诊断标签，广泛用于医学影像 AI 研究 |

## 五、非功能需求

### 5.1 覆盖度

- 单领域生成应确保各分类节点均有覆盖，产出总量以新增收敛为准，不低于试点验收门槛。
- 领域拆解应覆盖目标领域 ≥90% 的主要细分方向。

### 5.2 数据质量

- 输出数据源的有效 URL 占比 ≥80%（URL 需可达，即 HTTP 状态码非 4xx/5xx）。
- 输出结果去重率 ≥95%（同域名 + 同数据源名称应合并为一条）。

### 5.3 分类质量

- 分类路径层级清晰，≥90% 的数据源分类路径与其实际内容匹配。
- 分类体系内部术语一致，同一概念不出现多种表述。

### 5.4 可扩展性

- 系统应适配不同行业领域输入，不依赖领域特定硬编码规则。
- 新增领域无需额外开发配置即可运行。

### 5.5 可迭代优化

- 每次生成应记录效果数据，至少包含：生成耗时、产出数据源数量、有效 URL 占比、各节点覆盖情况。
- 无结果的搜索节点应单独记录，用于后续提示词和搜索策略优化。

## 六、边界与约束

### 6.1 初期不纳入范围

- 需账号权限才能访问的数据源
- 付费 / 商业数据源
- 非公开的私有数据源
- 数据源内容的深度质量评估

### 6.2 输入约束

- 单次输入为单个领域描述文本，长度不超过 200 字。
- 不接收结构化查询条件或多领域并行请求。

### 6.3 输出约束

- 单次输出为单领域的数据源清单，产出数量以各节点均匀覆盖、新增收敛为准，不设固定上限，不因追求数量引入低质量条目。
- 输出结果不包含数据源的实际数据内容，仅包含元数据描述。

## 七、验收标准

| 编号 | 标准 | 验证方式 |
|------|------|----------|
| AC-1 | 输入领域描述后可稳定产出数据源清单，无中断或异常 | 执行测试 |
| AC-2 | 试点领域单次产出数据源数量 ≥50 条 | 人工计数 |
| AC-3 | 输出数据源有效 URL 占比 ≥80% | HTTP 可达性检测 |
| AC-4 | 分类路径层级清晰，≥90% 分类合理无错配 | 人工抽查 |
| AC-5 | 去重后无同名同域名的重复条目 | 程序校验 |
| AC-6 | 支持至少 3 个不同领域的输入并产出合理结果 | 跨领域测试 |
