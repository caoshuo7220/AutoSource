# 存储架构改造方案（写入截断根治 · 定案版）

> 状态：**方案已定案（2026-08-28，四轮互评收敛），待实施**。本文件是实施时的唯一依据——所有组件规格、裁决理由、验收标准都在这里，实施时不重新决策。
>
> 阅读前提：docs/04 问题记录手册（P-005/P-007、讨论日志）、docs/07 根因分析（截断事故分析过程见本方案第 1 节引用的转录实证）。

## 1. 背景与根因

### 1.1 事故记录

2026-08-28 硬件总线接口规范轮（085759）：模型阶段 5 用一次 Write 写 raw.json（807 条 ≈ 240KB），生成被模型单回合输出上限截断，落盘的 raw.json 里 `sources: []`（合法 JSON、空数组）——脚本无从察觉，静默丢全量，靠用户手动指挥分卷写入才救回。

### 1.2 两轮转录逐条对比（实证，勿再复查结论）

| | 交换机轮（114546，813 条） | 总线轮（085759，840 条） |
|---|---|---|
| 表面结果 | "正常"完成 | 中途被用户打断，手动救援 |
| 真实写入过程 | 骨架检查点 15 次；18 分钟内宣告"写完整版" 9 次、每次只落盘 38KB 骨架；最终一次 218KB 完整写入侥幸成功 | 骨架 1 次（44KB）；试 Edit 分块追加被 outputs 权限拦截；被迫单次 ~260KB 大写入卡 13 分钟；用户打断 |
| 模型思考块证据 | 自知顶在输出上限、**主动压缩输出**（"minimal JSON, entries on single lines"） | 自估 ~260KB、决定"一次 Write，失败再适应" |
| 结论 | **两轮在同一边界掷硬币**——218KB 塞进边界内、~260KB 出界 | 同左 |

### 1.3 三层反模式诊断（根因，不只是"写入太大"）

1. **模型用 Write 倾倒大文件**——违反函数调用式小批量输出的行业标准模式
2. **单会话吞 250 次搜索结果 ≈ 40-50 万 token**——违反有界工作集
3. **证据校验拖到收尾才爆**——违反入库时校验（ETL 数据质量门）

截断只是第 1 层的最表面症状。本方案以"LLM 只做窄工具调用 + 小批量结构化输出；持久化、校验、对账全部由确定性代码持有"为总原则，同时解决三层。

## 2. 方案总览

```
初始化 --prepare → 预留 run_dir（不变）
阶段 0-1：拆解 + 知识清单 → Write manifest.json {domain, nodes, model}（一次，~几 KB）
阶段 2-4：每次搜索 → record_search(一条) + record_sources(新条目批次，入库即验)
          → coverage() 只查缺失 → 薄弱判定留模型 → 扩量到收敛
阶段 5：（删除——不再有"写 raw.json"这一步）
阶段 6：finalize(run_dir) 一次性折叠（复用 postprocess 引擎）→ 展示 stdout → 写分析报告（不变）
```

- 模型最大单次输出：manifest 几 KB、record 批次 2-8KB——离截断边界 30 倍
- store = JSONL 追加日志（事件溯源）；脚本持有全部数据文件
- raw.json 契约**取消**（sources/journal 走 store，元数据走 manifest）
- 证据 hook、权限白名单、报告强修法、分析报告模板——全部不动

## 3. 组件规格

### 3.1 store.jsonl（脚本持有，模型不可见）

追加日志，每行一条，脚本盖时间戳（模型无时钟）：

```jsonl
{"type":"source","node":"数据中心交换机","name":"...","category_path":"...","source_type":"...","granularity":"合集级","url":"...","description":"...","reason":"...","from_knowledge":false,"verified":true,"note":null,"ts":"..."}
{"type":"search","phase":"增量发现","node":"数据中心交换机","query":"...","results":10,"extracted":3,"ts":"..."}
```

- `from_knowledge`：知识清单条目标记（替代原 knowledge 数组；verified=true 的清单条目带 URL，入库即验；verified=false 的定案条目带 note="疑似无效机构"|"未找到官方入口"）
- 每条 knowledge 恰好 record 一次：验证通过的在阶段 2 当场 record；未通过的先不 record，扩量轮定案后按最终状态 record（避免覆盖更新的复杂性）
- 单次追加原子（append + flush），崩溃最多丢最后一个批次

### 3.2 MCP 工具四件套（stdio 服务，.mcp.json 注册，会话启动自动拉起）

**`record_sources(run_dir, entries[]) → {accepted, skipped, rejected:[{index, name, url, reason}]}`**

- 入库即验（逐条）：name/url 非空；url 走现有 `_contains_bounded` 证据校验（复用，含 `#` 豁免、`?` 严格）；granularity ∈ 合集级/单篇级（缺省合集级）
- 幂等：**裸 URL 精确相等**才跳过并计数（不归一化——见 8.1 裁决理由；真正去重仍由 finalize 域名+名称联合完成）
- 被拒条目逐个返回原因，其余照常入库——单条被拒不影响批次

**`record_search(run_dir, {phase, node, query, results, extracted})`**

- query 逐字比对证据留痕（现状机制），不在则标注"证据缺失"（同现状，不拒绝）

**`coverage(run_dir) → 每节点 {node, recorded, extracted, missing}`**

- 只读计数：recorded = store 中该节点 source 数；extracted = 该节点 journal 提取数之和；missing = max(0, extracted - recorded)
- **只测缺失，不测薄弱**（体裁/来源维度单一由模型在会话内判断，依据是它刚提取的内容；角度多样性脚本校验是 docs/07 §7 的独立账本项，不混入）

**`finalize(run_dir) → stdout 统计汇总（同现状收尾输出）`**

- 一次性折叠：读 store + manifest → 组装等价 raw 结构 → 复用现有 postprocess 全链路（证据终检/清单并入/去重/CSV/stats/溯源/搜索日志/目录重命名/归档）——**逻辑一行不改，只换入口**
- **防截断哨兵（保留）**：store 中 source 总数为 0 且 record_search 提取合计 > 0 → 拒绝折叠，显式报错"来源未入库，疑似违约未调用 record_sources"——模型若无视新契约、攒到最后直接 finalize，不会再静默丢数据
- manifest 缺失/损坏 → 显式失败，目录不重命名
- 收尾失败时不重命名目录、不清理——可安全重跑（幂等）

### 3.3 manifest.json（模型 Write 一次）

```json
{"domain":"交换机","nodes":["数据中心交换机","..."],"model":"当前实际模型名"}
```

- 阶段 0/1 结束后 Write 一次；**若需修正必须整体 Write 重写，禁止 Edit**（outputs 目录 Edit 被权限拦截，总线轮实证——Edit 墙是 08-28 事故的共犯）
- knowledge 不在 manifest（进 store，见 3.1）

### 3.4 postprocess.py 引擎化

- 拆为可导入函数模块（证据校验/清单并入/去重/CSV/stats/溯源/折叠）+ 原 CLI 入口保留
- CLI 行为不变（127 现有测试全过）；旧 raw.json 路径保留兼容（历史轮次/测试）
- MCP 服务 import 这些函数——无逻辑重复

## 4. SKILL 改造点（契约文本要点）

| 位置 | 改动 |
|---|---|
| 通用纪律/阶段 5 | **删除全部 raw.json 契约**；新增 record 三工具 + manifest 契约；"Write 直落、零转录、禁自创脚本"纪律迁移为"record 即落库、禁自创脚本" |
| 阶段 1 | 结束 → Write manifest.json |
| 阶段 2 | 验证通过 → record_sources（from_knowledge=true）；未通过 → 不 record，定案后 record |
| 阶段 3 | 每次搜索 → record_search + record_sources |
| 阶段 4 | coverage() 查缺失；薄弱判定规则不变（模型语义判断）；扩量轮补充 → record |
| 阶段 6 | 收尾 = finalize(run_dir) + 报告（`--rename-report` 不变） |
| 失败路径 | 不变（搜索大面积失败 → 不 finalize、显式声明失败） |

钉桩测试覆盖：新契约文案在、raw.json 契约句不在、manifest 禁 Edit 句在。

## 5. 配置与权限

- `.mcp.json`（项目级，git 跟踪）：注册 stdio MCP 服务；用户首次信任一次
- settings.json：白名单、hook 全部不动
- 会话启动生效（与 hook 同理）——改配置后新会话生效

## 6. 验收标准（不变量层级）

1. 交付物四件套（清单 CSV/stats/分析报告/搜索日志）内容语义与旧契约完全一致（逐列口径不变）
2. 入库即验：无证据 URL 当场拒绝并反馈原因，finalize 零新增拒绝
3. 截断场景（store 空 + 提取 > 0）→ finalize 拒绝并显式报错，目录不被重命名
4. 旧契约兼容：无 store/manifest 的旧 raw.json 走 CLI 结果不变
5. 单次模型输出上限：manifest ≤ 10KB、record 批次 ≤ 20KB（截断边界 30 倍余量）
6. 127 现有测试 + 新增测试全过
7. 证据 hook/权限白名单/强修法/报告模板无改动

## 7. 测试面清单（TDD 顺序）

1. store 追加/坏行处理/空批
2. record_sources 校验（证据链复用、粒度枚举、必填、裸 URL 幂等跳过计数、单条拒收不阻断批次）
3. record_search 查询词比对与"证据缺失"标注
4. coverage 按节点计数（category_path 末段分组、跨节点归因口径）
5. finalize 折叠（store+manifest → 等价 raw → 全链路产物；哨兵；manifest 缺失；重跑幂等）
6. 旧 CLI 全量回归
7. SKILL/配置钉桩（新契约文案、manifest 禁 Edit、.mcp.json 存在）
8. MCP 协议层（stdio 握手、工具路由）

## 8. 裁决记录（实施时不重新决策）

### 8.1 已裁决并纳入方案

| 评审点 | 裁决 | 理由 |
|---|---|---|
| raw.json 五块字段归属 | 瘦身不取消：sources/journal→store；domain/nodes/model→manifest；knowledge→store（from_knowledge 标记） | finalize 的目录命名/空节点检测/清单并入/stats 全靠元数据 |
| manifest 重写方式 | 整体 Write、禁 Edit | Edit 在 outputs 被权限拦截（总线轮实证） |
| 幂等键 | 裸 URL 精确相等 | 归一化会合并 query 差异（语言版本偏好规则下是不同内容）；`?` 严格是 6064593 纪律；去重键形式化是 P-007 账本项 |
| coverage 范围 | 只测缺失 | 薄弱判定是语义判断，留模型；角度多样性校验是独立账本项 |
| finalize 性质 | 一次性折叠，不做增量 postprocess | 聚合操作留收尾；"边收边跑"仅指 record（追加）+ coverage（只读） |
| run_dir 传参 | 工具参数，照抄 --prepare 路径 | 与现状 postprocess 收路径同构 |

### 8.2 明确不做（挂账本，含触发条件）

| 项 | 不做的理由 | 触发条件 |
|---|---|---|
| URL 引用制（链接编号代 URL） | 入库即验让照抄错误当场可见可修，其价值被压缩；且引入"编号数错→静默挂错"新风险类 | 照抄拒绝率持续 >5% 或成为主要损耗时重启 |
| 断点续跑模式（kill 后接着跑） | 至今零 kill 案例；store 已存全部 journal，门已留好 | 出现首个运行中途 kill 案例时补 SKILL 恢复章节（非架构改动） |
| 子代理工作者（每节点一个） | 上下文膨胀尚未造成实际失败（总线轮 250 次搜索 ≈ 半窗）；+40% token、编排新方差、断点事故疤 | 单轮搜索 >~400 次或会话后段提取率塌陷时启用（同工具零返工） |
| 角度多样性脚本校验 | 独立账本项（docs/07 §7） | 选题塌方复现时实施 |
| P-007 去重键归一化、源头2 标签规范化、并行实测 | 既有悬置项，与本次无关 | 见 docs/04 问题清单（P-007）与讨论日志 |

## 10. 历史教训映射（实施时对照）

- **Edit 墙**（总线轮）：契约只允许 Write
- **断点事故**（平板轮）：流程线性不变，finalize 就是收尾最后一步，无交接
- **提示词约束不可强制**：模型可能违约不调 record_sources → finalize 哨兵兜底，失败响亮
- **build_raw.py 事件**：模型禁止任何自创脚本组装——record 工具就是组装环节的脚本化归位
- **无人值守容错**：单条被拒不阻断批次；finalize 永不因被拒中止（隔离计数，现状机制不变）
