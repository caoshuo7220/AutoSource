# AutoSource 项目交付手册

> 本文档面向接手的 AI/开发者。阅读完本文档后，你应当能够理解项目全貌、当前状态、既有决策的原因，以及下一步该做什么。

## 1. 项目是什么

AutoSource 是一个 **Claude Code Skill**——用户在对话中输入 `/autosource <领域描述>`，Claude 自动完成"领域拆解 → 数据源搜索 → 去重整理 → 导出 CSV"全流程，产出该领域的公开数据源清单。

核心价值：替代人工梳理数据源的工作，把"找数据源"这件事自动化。

```
输入: /autosource 算力服务器
  ↓
产出: outputs/算力服务器_2026-08-13-173232/
      ├── 算力服务器_2026-08-13-173232_数据源清单.csv   ← 交付物（UTF-8 BOM，Excel 直接打开）
      ├── {领域词}_{时间戳}_分析报告.md      ← 交付物（领域分析：概览/技术格局/产业生态/标准体系/中外对比/趋势观察）
      ├── {领域词}_{时间戳}_运行验收单.json                    ← 验收单（本轮体检：条数/拒绝原因/零提取理由/配额/对账；脚本生成，docs/06 第 2 期）
      └── intermediate/                             ← 排障与对比材料（发现问题时才查）
          ├── {领域词}_{时间戳}_stats.csv    ← 清单统计（每节点条数/体裁分布 + 总计行；跨轮对比用）
          ├── {领域词}_{时间戳}_搜索日志.csv ← 搜索复盘（每次搜索的查询词/提取数）
          ├── {领域词}_{时间戳}_溯源.csv     ← 数据血缘（正查/反查：结果与收录对应）
          ├── store_input.jsonl             ← 存储快照（record 工具落库的原始 store）
          ├── manifest_input.json           ← 清单快照（声明版/最终核对态归档）
          └── evidence_log.jsonl            ← 证据留痕（本运行切片，调试/复盘）
```

每条数据源包含 7 个字段：数据源名称、分类路径、数据源类型（内容体裁）、粒度（合集级/单篇级）、访问地址、简要说明、来源搜索（该 URL 在留痕中首次出现的查询词；多出处见溯源.csv）。

## 2. 项目背景与边界

- **为什么做**：上游数据源此前依赖人工梳理提名，存在覆盖度低、体系性弱、人力成本高的问题，受限于个人视野难以实现行业级全域覆盖——本项目以 AI 驱动的自动发现替代人工梳理（源自需求文档，2026-08-31 并入本手册）
- **用户职责**：只负责"数据源发现与产出"，不关注下游采集链路（采集有另一套 caiji 系统处理）
- **"数据源"的含义**：泛指一切泛化信息载体——官方文档、技术手册、知识库、API 文档、论文、数据集、开源仓库、排行榜、行业标准、技术博客、资讯平台等。**数据集只是其中一类，不应占主导**
- **边界**：不含需账号权限、付费、非公开的私有数据源
- **通用检索入口（不进清单，供下游自行查用）**：知网 CNKI、Google Patents、维基百科/百度百科、全国标准信息公共服务平台、工标网、万方等跨领域恒定平台，不作为发现结果输出（决策 19）；下游如需按领域补充检索，可自行使用这些入口

**分层架构**（参照了用户已有的 caiji 采集系统模式）：

| 层 | 文件 | 职责 |
|----|------|------|
| Skill | autosource/SKILL.md | 单一线性流程（阶段 0-6）：领域拆解、**知识清单**（权威源按叶节点归类）、完整性自检、**验证搜索**（清单逐项验证，核对结果随验证过程走 record_knowledge 落库）、**增量发现**（每节点 20 次（固定 4 + 自由 8 + 实体 4 + 扩充 4））、覆盖评估与扩量、**manifest 单次 Write（阶段 0-1）+ 阶段 5 清单了结自检**、**收尾 finalize 折叠并输出最终汇总**（无中间停靠点） |
| 后处理 | autosource/scripts/postprocess.py + evidence.py / lineage.py / report.py（2026-09-02 自 postprocess 拆分的子模块：证据链 / 数据血缘 / 报告注入） | 确定性流水线：证据校验（被拒条目不进清单，明细见 finalize 返回文本/计数见 stats）、**清单并入与验证率**（store 核对记录与声明清单对账）、去重、CSV 导出（含来源搜索列）、stats、**搜索日志**、**数据血缘溯源.csv（正查/反查）**、**归档**（清单在根，stats 与排障材料入 intermediate/）、清理；`fold()` 读 store+manifest 组装等价 raw 后复用本流水线（docs/04 存储改造） |
| 存储层 | autosource/scripts/store.py + mcp_server.py | **数据落盘走 MCP 五工具**（docs/04）：record_sources 批次入库即验（URL 逐字比对证据留痕、当场拒绝+反馈、裸 URL 幂等）、record_search 搜索日志批量入库、**record_knowledge 清单核对批次入库**（verified=true 必带 url 且过证据链，同名重录=状态更新）、coverage 只测条数缺失、finalize 收尾折叠（含防截断哨兵 + 清单了结哨兵）——模型不 Write 数据文件，单次输出 ≤ 一个节点批次；元数据走 manifest.json（模型 Write 一次：阶段 0-1 声明版，禁 Edit） |
| 证据留痕 | autosource/scripts/evidence_hook.py + settings.json hook | PostToolUse hook 系统记录每次搜索原始结果；脚本校验 URL 与查询词必须逐字在留痕中，从结构上杜绝模型编造 |

**设计原则：LLM 负责"懂"，脚本负责"确定性的活"。** 推理和判断在 SKILL.md 指令里；时间戳、去重、CSV 编码、stats 统计这些有标准答案的环节全部在 Python 脚本里（P-005 的结论，见 02-日志手册 2026-08-13 条目）。数据落盘走 MCP 工具（入库即验），元数据走 manifest.json——模型不 Write 数据文件、零转录。

## 4. 关键决策记录（接手必读）

以下是迭代过程中踩坑后形成的决策，**不要轻易推翻**：

| # | 决策 | 原因 |
|---|------|------|
| 1 | 分类层级深度不固定 | 不同领域自然深度不同（金融 4 层、开源框架 2 层），由模型按领域决定 |
| 2 | 数据源类型预设 12 类封闭词表（2026-09-07 修订，原"不预设枚举"作废） | 开放词表 45 轮实测产出 332 个散词、头部 16 词覆盖 98%——长尾是噪声不是新形态，自由填写必然子集分裂、体裁分布无法横向对比。改为封闭词表（文档/官网/标准/报告/文献/专利/数据集/数据库/代码仓库/知识库/社区/媒体 + 其他兜底）：单字段纯载体维度互斥，词表与别名在 store.py（SOURCE_TYPES/SOURCE_TYPE_ALIASES），入库即归一 + 收尾再归一（幂等，双入口一致），表外词落「其他」并进审计行，可补别名收敛 |
| 3 | 每次运行独立时间戳目录 | 同领域多次运行不覆盖，可对比效果 |
| 4 | 领域词由输入提炼（2-6字），不用原始输入做目录名 | 用户可能输入 200 字长句 |
| 5 | 搜索用"发现型关键词"，禁搜产品规格 | 搜"GPU 排名 数据库"能挖出资源集合；搜"H100 规格"只锚定单一产品页 |
| 6 | 厂商/产品名按意图区分 | 禁搜规格参数页，但允许搜文档站/知识库/API 入口（高价值成体系知识源） |
| 7 | 双维度搜索（组织形式 + 体裁入口）× 中英文 | 既拿"整理好的资源集合"，也拿"权威内容入口" |
| 8 | 提取阶段不做数量筛选 | 提取不设条数上限（产量优先）；减法分两处——提取端逐条判断、三类不收（无关噪声/通用平台首页/已收录重复），去重端幂等去重 |
| 9 | URL 校验已移除 | 校验误杀严重（反爬 403、国内网络超时），当前聚焦搜索问题，校验以后再说 |
| 10 | 每节点统计候选数+体裁分布 | 薄弱节点判定用（数量少 或 体裁单一），写入 stats.csv 供迭代 |
| 11 | 拆解后做完整性自检 | 自问"有没有漏掉的公认子方向"（例：算力服务器补入 ARM/国产处理器） |
| 12 | 权限走 settings.json 项目级分发 | 使用者 clone 后首次确认一次，之后不再弹窗；2026-08-18 起运行期/开发期分层——settings.json 只留流水线最小集（搜索/读/outputs 读写/postprocess/MCP 入库工具规则），开发期便利项（python -c/pip install/git 等）在 settings.local.json（gitignore，不分发） |
| 13 | CSV 文件名带领域词+时间戳 | 多次运行的清单要能同时打开对比，Excel 不允许打开两个同名文件；文件名自描述，脱离目录也能识别 |
| 14 | 时间戳由脚本生成，模型禁止编造 | 模型没有时钟，曾编出与实际差 3 小时的时间戳；且两次运行若编出相同时间戳会互相覆盖 |
| 15 | stats 输出用 CSV 长表，命名与数据源清单同步 | 原 stats.json 不便在 Excel 查看；CSV 可直接打开、多次运行横向对比，文件名带领域词+时间戳。2026-08-21 起瘦身为纯清单统计表：分类节点/候选数/体裁分布每节点一行 + 末尾"总计"行；运行级信息在文件名（领域/时间戳）、manifest.json（模型）、stdout（过程健康指标） |
| 16 | 确定性环节全部代码化，LLM 只产 raw.json | 时间戳编造、CSV 转义错误、stats 口径不一致等实测问题均源于 LLM 手工执行确定性步骤；脚本可测试、可复现（P-005 结论）。2026-08-20 补强：raw.json 改由搜索层直接落盘、编排层零文件写入（build_raw.py 事件——编排层自创脚本组装大 JSON 触发弹窗，证明组装本身是确定性环节，归位） |
| 17 | 证据留痕 + grounding 校验防 URL 编造 | 实测发现候选里混入凭记忆补的 URL（dentOS/Stratum）。指定工具管不住字段级幻觉，提示词约束不可强制；由系统 hook 记录搜索证据、脚本逐字校验 URL（2026-08-18 起为边界匹配，截短为父路径/裸域名不放行），意外编造从概率问题变成结构上杜绝（留痕文件无写保护，不防对抗性篡改） |
| 18 | 两路发现：知识清单 + 验证搜索 + 增量发现 | 单路搜索无法保证"该有的都有"——先由领域知识点名权威源（URL 留空）、搜索验证（幻觉被挡在未验证清单）、再增量补充；清单验证是自洽性指标不衡量完整性。展开挖掘整体抛去（D3）。决策集 D1-D11 见 02-日志手册文末附录 |
| 19 | 通用平台不作为独立条目 | 实测清单混入知网/Google Patents/标准平台等跨领域通用平台——无主题边界（违反 P-002）、平台首页 URL 下游采集不到领域内容、人尽皆知纯噪声。判据：条目 URL 必须定位到该领域的内容；平台信息通过领域条目描述传递；跨领域恒定入口写在本手册第 2 节供下游自行查用 |
| 20 | 粒度矛盾脚本检测 | 曾实施后按用户决策**移除**（2026-08-20）：产量优先、粒度/子站问题由后续"站点与子站合并"功能处理；granularity 声明保留为信息展示（清单"粒度"列 + 单篇级收录计数），不再拒绝 |
| 21 | 单 skill 合并（skill 规范） | 2026-08-24 按 skill-creator 规范评审：skill 的设计单位是"用户意图触发的工作流"，搜索/验证/提取/后处理是同一工作流内部阶段，独立子 skill 触发面为空、违反"description 承载 when-to-use"的设计。合并为单一 autosource skill（SKILL.md 线性流程 阶段 0-6），脚本归位 scripts/；收尾仍为最后一步，无中间停靠点不变 |
| 22 | 领域分析报告（第三交付物） | 2026-08-25：数据源是输入、领域洞察是产出——收尾最后一步按模板写分析报告.md（概览/技术格局/产业生态/标准体系/中外对比/趋势观察六板块）；模板按 progressive disclosure 放 references/，SKILL.md 只留指针；依据锚定 + 免责声明两条纪律防模型空谈；脚本零改动（报告为模型产物） |
| 23 | 存储架构改造（写入截断根治） | 807 条写入事故确诊三层反模式（大文件倾倒/无界工作集/收尾才校验）后定案：数据落盘走 MCP 工具（入库即验+批量落库+coverage+finalize）、store.jsonl 事件流、manifest 元数据、防截断哨兵——模型不写数据文件，截断在机制上不可能。2026-08-31 验收通过。详见 docs/04 |
| 24 | 清单核对结果走 record_knowledge（2026-09-08 修订，推翻决策 23 的"清单走 manifest"部分） | 214051 轮实证：阶段 5 手工转写 65 条清单 JSON 漏写 60 个 verified 字段（finalize 如实报 0/65 后模型违规手动收尾、烧 7 分钟上下文）——转写是必然出错的事故类型，且与压缩丢失风险同源。改为第五工具 record_knowledge：核对结果随验证过程分批落库（verified=true 入库即验证据链，同名重录=状态更新），manifest 只写一次（阶段 0-1 声明版），阶段 5 改清单了结自检，finalize 加清单了结哨兵（声明项无记录拒绝收尾并点名）；旧归档 manifest 最终核对态走兜底路径兼容 |

## 6. 已知问题与限制

1. **集合页展开（WebFetch）已从流程移除，裁决不再恢复**（两路方案决策 D3，2026-08-14；2026-08-31 裁决关闭恢复窗口）：搜索富摘要已承担部分展开价值、当前主要矛盾是质量而非数量、环境域名验证受限；长尾覆盖不作为方向（curl 实测记录见 05-参考方案手册第 4 节）
2. **URL 可达性校验已移除，裁决不再恢复**（决策 9；2026-08-31 裁决关闭恢复窗口）：校验误杀严重（反爬 403、国内网络超时）——浏览器 UA、放宽超时、白名单域名等缓解手段均不实施；AC-3 标准相应废弃
3. **stats.csv 无自动消费端**：目前只供人工对比。caiji 系统有 verify-report 自动回炉闭环，这里还没有
4. **证据留痕 hook 在会话重启后生效**：settings.json 的 hook 在会话启动时加载；本会话中修改后需重启会话（或信任项目后新开会话）才会触发。hook 生效前 postprocess 会因"证据留痕不存在"拒绝处理（设计使然，不是缺陷）

## 9. 术语表

本表是项目术语的唯一定义处，其余文档只用不解释：

| 术语 | 含义 |
|------|------|
| 运行 | 一次 `/autosource` 的完整执行。历史讨论中用"XX 轮"指代某次运行（如"交换机轮""总线领域轮"），只出现在 02 讨论日志 |
| 领域词 | 从用户输入提炼的 2-6 字核心关键词（如"交换机"），用于运行目录命名 |
| 领域拆解 / 节点 | 把领域拆成树状分类；叶子节点是搜索骨架的最小单位 |
| 知识清单 | 拆解后凭领域知识列出的权威源名单（URL 留空待验证）。注意与交付物"数据源清单"区分 |
| 数据源清单 | 交付物 CSV——最终收录的数据源（7 列） |
| 验证搜索 / 增量发现 | 搜索的两个环节：逐项验证知识清单 / 找清单之外的源 |
| 覆盖评估与扩量 | 逐节点检查候选数与体裁、来源维度覆盖，薄弱节点补搜 |
| 清单验证 | 自洽性指标（模型列清单→模型搜索验证），**不衡量对真实世界的完整性** |
| 证据链 / 证据留痕 | hook 自动记录的每次搜索原始结果；候选 URL 必须逐字在其中，否则拒绝 |
| 入库即验 | 候选落库时当场校验证据链并反馈拒绝原因，而不是收尾时集中校验 |
| 搜索日志 | intermediate/ 下的 CSV——每次搜索的查询词/返回数/提取数（journal 落盘） |
| 溯源 | intermediate/ 下的 CSV——数据血缘：结果 URL ↔ 收录条目 ↔ 查询词的对应关系 |
| 收尾（finalize） | 运行最后一步：脚本折叠 store+manifest，一次产出全部交付物并归档排障材料 |
| 防截断哨兵 | 收尾内置防护：store 空但搜索有提取时拒绝收尾并报错（防静默丢数据） |
| 粒度 | 合集级（有主题边界的成体系入口）/ 单篇级（单页/单文件），每条候选声明其一 |
| 体裁 | 数据源的内容形态标签（文档/官网/标准/报告/文献/专利/数据集/数据库/代码仓库/知识库/社区/媒体/其他），12 类封闭词表 + 其他兜底，见决策 2 与 SKILL.md「数据源类型」段 |
| 来源角色 | 谁发布：标准组织/厂商/研究机构/评测机构等，用于覆盖检查 |
| 报告统计注入 | 分析报告的"数据总览"由脚本从交付物生成，模型不写任何统计数字 |
| 待办账本 / 挂账 | 03-待办账本.md：缓做/不做/待验证事项的登记处；挂账=暂不实施、带触发条件 |
| 钉进测试 | 把约定/契约写进自动化测试断言，防止规则漂移（约定不靠自觉） |
| 防自锚定 | 禁止模型读历史运行产物（权限规则+提示词双重拦截），防上次结果成为基线极化 |
