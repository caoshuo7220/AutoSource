# AutoSource Skill 实施计划

> 本计划已执行完成。文档保留作为架构和维护参考。

**Goal:** 创建一个 Claude Code Skill——用户输入 `/autosource <领域>`，Claude 在对话中自动完成领域拆解、Web 搜索、数据源整理、去重校验、导出 CSV 全流程。

**Architecture:** `autosource`（单一 skill，线性流程）+ `scripts/postprocess.py`（后处理流水线）+ `scripts/log_tool.py`（证据留痕）+ `settings.json`（权限分发）。skill 内一条指令链从领域拆解直通收尾（阶段 0-6），后处理脚本保证全部确定性环节（时间戳/目录命名/去重/CSV 导出/stats/清理）。2026-08-24 起原 `autosource-search`（搜索层）按 skill 规范并入（详见 05-交付手册 决策 21）。

**形式:** Claude Code Skill（`.claude/skills/autosource/`），通过 `/autosource` 斜杠命令触发。

## 文件结构

```
.claude/
├── settings.json                         ← 项目级权限（WebSearch/Bash/Write 等，Git 跟踪分发）
└── skills/
    ├── autosource/
    │   ├── SKILL.md                      ← 单条线性流程：拆解 → 知识清单 → 验证搜索 → 增量发现 → 扩量 → 收尾
    │   └── scripts/
    │       ├── postprocess.py            ← 后处理流水线：证据校验+去重+CSV 导出+stats+清理
    │       └── log_tool.py               ← PostToolUse hook：系统记录搜索证据留痕
tests/
├── __init__.py
└── test_postprocess.py                   ← 单元测试，全部通过
docs/
├── 01-需求文档.md
├── 02-搜索方案.md
├── 03-实施计划.md
├── 04-问题记录手册.md
└── 05-交付手册.md
```

**用户输入输出：**

```
输入: /autosource "帮我收集AI训练GPU算力服务器相关数据源"
  ↓
Claude 按 SKILL.md 执行:
  1. 提炼领域词 → "算力服务器"
  2. 领域拆解 → 树状分类（含完整性自检）
  3. 知识清单 → 领域公认权威源按叶节点归类（零搜索，URL 留空，含清单自检）
  4. 验证搜索 → 清单逐项验证（URL 照抄入清单项）；增量发现 → 双维度×中英文 4 次/节点（粒度规则：合集级为主）
  5. 覆盖评估与扩量（薄弱判定含清单验证状态；终止条件含清单收敛）
  6. 按契约写入 raw.json（domain/nodes/model/knowledge/journal/sources）到 outputs/raw.json（Write 直落、零转录，2026-08-20 起）
  7. 收尾运行 postprocess.py：证据校验 → 清单并入 → 去重 → 导出数据源清单 CSV → 写 stats CSV（含清单验证列）→ 写搜索日志 CSV → 清理 raw.json 与留痕
  8. 汇总报告（基于脚本 stdout 统计 + 清单核对 + 未验证清单）
```

## 全局约束

- Skill 安装在 `.claude/skills/autosource/` 目录
- `/autosource` 命令接收领域描述（必填）+ 可选 `-c` 分类路径 + 可选 `-t` 类型限定
- 最终交付物：CSV（UTF-8 BOM，中文表头），放在 `outputs/{领域词}_{时间戳}/{领域词}_{时间戳}_数据源清单.csv`（文件名带领域词+时间戳，多次运行可同时打开对比）
- 同领域多次运行不覆盖（时间戳区分）
- 领域词由系统从用户输入中提炼为 2-6 字核心关键词，不等同于用户原始输入
- postprocess.py 仅依赖 Python 标准库
- 搜索使用 Claude Code 自带的 web_search 工具
- 权限通过 `.claude/settings.json` 随仓库分发，用户首次 clone 后确认一次即可

## 已完成的 Tasks

### Task 1: SKILL.md（顶层流程）

- 定义 `/autosource` 命令的完整流程：领域拆解 → 知识清单 → 验证搜索 → 增量发现 → 扩量 → 写入 raw.json → 收尾
- 2026-08-24 起：按 skill 规范合并为单一 skill（原 Task 1b 的 autosource-search 并入），脚本归位 scripts/

### Task 1b: autosource-search（搜索层）——已并入（2026-08-24）

- 接收叶子节点列表，对每个节点执行发现型搜索
- 核心原则：搜索"整理好的资源集合"（数据库/排名/列表/标准），不搜具体产品名
- 每个节点中英文各搜一次，从搜索结果中提取全部合格数据源
- 第一轮后覆盖评估，薄弱节点自动扩量

### Task 2: postprocess.py（后处理流水线）

- `deduplicate()`：按域名 + 数据源名称联合去重，镜像站保留
- 脏数据容错：缺 name/url 的记录跳过并计数，不中断整批
- 时间戳与输出目录由脚本系统时钟生成（同秒冲突自动加后缀），模型不参与命名
- CSV 导出用 csv 标准库（UTF-8 BOM、标准转义）；stats 由脚本计算并写 stats CSV
- 完成后删除 raw.json 与证据留痕（`--keep-raw` 可保留供审计）
- 单元测试覆盖全部功能

### Task 2b: 证据留痕与 grounding 校验

- `log_tool.py`：PostToolUse hook 脚本，harness 在每次 WebSearch/WebFetch 后自动把原始结果追加到 `outputs/search_log.jsonl`（系统记录，模型不可篡改）
- `check_grounded()`：候选 URL 必须逐字出现在证据留痕中，否则拒绝并计数（stdout 与 stats CSV 可见）
- 留痕缺失且存在候选时脚本报错拒绝处理——没有证据链就不放行，设计使然
- hook 配置在 `.claude/settings.json` 随项目分发（会话启动时加载，修改后需重启生效）

### Task 3: 两路搜索方案实施（见 02-搜索方案.md）

- 编排层新增"知识清单"步骤（零搜索列权威源，含按机构类型维度的清单自检），raw.json schema 增加 `knowledge` 与 `journal`
- 搜索层新增"验证搜索"（清单逐项验证，失败分"疑似无效机构/已尽力"两类处置），增量发现压缩为 4 次/节点，粒度规则（合集级为主，判定话术 + reason 字段），薄弱判定与终止条件按清单验证状态重定义，移除集合页展开段落，按接口契约输出
- postprocess.py 新增：`merge_knowledge()`（verified 项自动并入 sources）、清单验证率计算、journal 查询词证据校验 + 搜索日志.csv 生成、stats CSV"清单验证"列、stdout 未验证清单
- 单元测试 25 → 41 个

### 权限配置

- `.claude/settings.json`：项目级权限白名单（WebSearch、Write/Read/Edit、Bash），随 Git 分发
- `.claude/settings.local.json`：个人本地配置，Git 忽略
