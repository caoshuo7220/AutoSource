# AutoSource 2.0 设计文档

> 状态：已定稿。
> 定稿日期：2026-09-03
> 说明：本文档为 AutoSource 2.0 的设计说明，供新环境独立开发使用。1.0 沉淀的领域知识已搬运至本文档（见"复用边界与领域知识沉淀"章节），开发者无需查阅 1.0 实现。

## 一、项目定位

AutoSource 2.0 的目标：系统性地发现指定领域的公开数据源，输出结构化清单。

核心演进方向：将线性流水线（按固定流程执行完毕即终止）演进为收敛式循环（在搜索过程中持续深化对领域的理解，并以该理解驱动后续搜索，直至领域覆盖充分、探索收敛）。

## 二、设计决策

### 目的

输出指定领域的数据源清单。

### 核心机制

以下三项机制是同一演进方向的三个层面：

- 领域理解：为循环提供方向依据；

- 反馈闭环：将搜索发现反向作用于后续搜索规划与领域结构修订；

- 收敛判据：定义循环终止条件，不以固定搜索次数为限，而以探索收敛为准。

### 实现形态

采用宿主内 Skill 形式（SKILL.md 编排指令 + Python 脚本），由宿主（TRAE / Claude Code）读取并执行，无独立进程。

- 宿主负责搜索执行：调用其内置 websearch 工具（免费、国内可用）；

- 脚本负责确定性环节：循环控制、状态管理、收敛判定、证据校验、去重、记录；

- LLM 负责语义环节：规划、提取、评审；

- 循环控制权下沉到脚本：脚本持有状态、执行收敛判定、决定继续或终止，不依赖 SKILL.md 散文指令自觉循环。

### 循环流程（六个步骤）

1. 规划（LLM）：读取当前状态，生成一组（3-5 个）查询词及规划依据；
2. 搜索（宿主）：调用宿主内置 websearch 工具批量执行该组查询词；
3. 提取（LLM）：逐条判断是否纳入收录，并提取新实体、子方向、术语；
4. 状态更新（脚本）：执行证据校验与去重，更新源集合、领域结构、探索记录；
5. 评审（LLM）：读取状态，生成缺口清单与覆盖充分性判断；
6. 收敛判定（脚本）：校验客观覆盖条件与 LLM 确认结果，决定终止或继续；达到批次上限则强制终止。

### 职责分工

- 宿主负责搜索执行：调用内置 websearch 工具；

- 脚本负责确定性环节：循环控制、状态管理、收敛判定、记录、证据校验、对账；

- LLM 负责语义环节：规划、提取、评审。

### 搜索粒度

每次规划生成一组查询词（3-5 个），完成一组搜索后执行一次评审。

### 流程结构与循环

循环由脚本驱动，无图状态机。流程步骤为 `init → plan → search → extract → commit → review → finish`，其中 `plan → search → extract → commit → review` 构成循环体；`review` 之后由脚本判定继续（返回 plan）或终止（进入 finish）。搜索步骤由宿主执行，其余步骤由脚本与 LLM 协作执行。状态以序列化 JSON 文件保存，为断点续跑预留能力；人工介入由宿主原生承载。

### 状态字段

- 领域结构（树形）节点包含 6 个字段：`name / parent / terms / entities / dims（适用维度，由 LLM 维护）/ angles（已搜索角度，由脚本维护）`；

- 源集合包含 6 个字段：`name / url / source_type / granularity / node / description`；

- 探索记录包含：搜索历史（query / node / 结果数 / 去重后新增数）、缺口清单（描述 / 归属节点 / 状态）、循环统计（连续无新增批次计数）；

- 状态设计原则：状态仅记录事实，不记录判断。

### 收敛判据（三层）

1. 脚本校验客观覆盖条件：所有节点的 `dims - angles` 为空，且缺口清单为空，且连续 K 批次无新增；
2. LLM 确认：客观覆盖条件达成后，由 LLM 确认领域覆盖充分；
3. 强制终止：总批次数达到上限，强制终止。

   - 终止条件 =（客观覆盖条件达成 且 LLM 确认）或（达到批次上限）；

   - 连续无新增是"调整探索方向"的信号（由 review 内部处理），而非终止信号。

### 失败处理（两层）

1. 单次查询失败：最多重试 2 次，仍失败则跳过该查询，并在探索记录中标记失败；
2. 连续 2 批次失败率 ≥ 50%：判定搜索服务异常，中止循环，保留状态并声明失败（不丢弃已收录的数据源）。

### 评审产出格式

- 缺口清单（写入探索记录）：`{描述, 归属节点, 状态: 未补/已补}`；

- 覆盖充分性判断（写入状态，供收敛判定读取）：`{收敛: bool, 理由: str}`。

### LLM 节点接口契约（4 个 LLM 节点）

| 节点      | 输入                 | 输出                                                |
| ------- | ------------------ | ------------------------------------------------- |
| init    | 领域描述               | nodes（name / parent / terms / dims）               |
| plan    | 领域结构 + 缺口清单 + 搜索历史 | queries（query / node / angle / reason）            |
| extract | 搜索结果               | sources + new\_entities + new\_terms + new\_nodes |
| review  | 状态                 | gaps + converged + reason                         |

三项约束：

1. plan 的 `angle` 通常取自该节点的 `dims`，允许填入搜索中新发现的维度；
2. extract 的 `url` 须与搜索结果逐字保持一致（证据校验要求）；
3. 所有输出须为合法 JSON（脚本需解析）。

### 预留功能

- 断点续跑：由状态序列化文件预留（运行开始时读取状态文件决定续跑起点）；

- 人工介入：由宿主原生承载（宿主 Agent 天然支持暂停与用户交互）。

## 三、技术栈与环境

- LLM：公司 OpenAI 兼容网关（OpenAI Chat Completions 协议），支持 function calling；模型与 base\_url 由部署配置注入（实测模型为 deepseek-v4-flash）；无内置搜索服务。

- 搜索：宿主内置 websearch（TRAE / Claude Code 提供），免费且国内可用。不接入外部搜索 API（Tavily / SerpAPI / Brave 等收费且受国内网络限制，公司内部亦无搜索服务）。

- 编排：宿主内 Skill（SKILL.md + Python 脚本），无独立进程、无图状态机。

- 状态存储：序列化 JSON 文件（状态仅记录事实）。

- 运行环境：Python 3（脚本）；宿主 Agent（编排与搜索执行）。

## 四、复用边界与领域知识沉淀

2.0 复用 1.0 沉淀的领域知识（作为 LLM 节点 prompt 的语义规则），重写控制流（线性流水线 → 收敛循环）。以下知识已搬运至本文档，开发者无需查阅 1.0。

### 复用部分

- 领域知识：搜索词构造词类、角度池、实体选题规则、易失效角度规则、平台准入判据、粒度规则、语言版本偏好、证据链规则、数据源类型标签（见下文）；

- 交付物格式：数据源清单（CSV）、分析报告、统计（stats）。

### 重写部分

- 控制流：线性六阶段 → 收敛循环；

- 状态管理：无 → 序列化状态文件（领域结构 / 源集合 / 探索记录）；

- 脚本职责：事后统计 → 过程控制（状态持有 + 收敛判定）；

- LLM 接口：四节点契约（init / plan / extract / review）。

### 领域知识明细

#### 搜索词构造词类

1. 组织形式词：数据库、排名、列表、标准、仓库、数据集、文献库、合集等；
2. 体裁 / 入口词：官方文档、开发者文档、technical documentation、手册、知识库、API 参考、帮助中心、白皮书、论文文献、专利、市场研究等；
3. 来源角色词：标准组织、监管机构、政府部门、行业协会、厂商、研究机构、大学、评测机构、基金会、公共数据平台等；
4. 厂商 / 产品名规则：不单独搜产品名、不搜单个产品的规格参数页；搜厂商 / 产品的文档站、知识库、API、帮助中心入口。

#### 角度池（六类）

- 学术类：论文 / 专利；

- 组织形式类：列表 / 排名 / 数据库 / 标准 / 仓库 / 合集；

- 体裁类：官方文档 / 手册 / 知识库 / 白皮书；

- 数据类：数据集 / 开放数据；

- 生态类：社区 / 博客 / 资讯平台；

- 来源角色类：标准组织 / 监管机构 / 政府部门 / 行业协会 / 厂商 / 研究机构 / 大学 / 评测机构 / 基金会 / 公共数据平台。

#### 实体选题规则

- 实体 = 机构 / 厂商 / 产品 / 规范等具体对象；

- 查询词 = "实体名 + 入口词"，可不含领域词；

- 只收该实体的成体系载体入口，不收单篇规格页。

#### 易失效角度规则

- 论文 / 专利 / 标准三类角度必须组合"领域词 + 入口词"（检索 / 列表 / 分类 / 目录 / 合集），否则命中通用平台首页被拒收；

- 英文查询避免未组合泛化后缀（list / standard list / directory / registry / collection），优先"领域词 + 厂商内容入口词"（documentation / official docs / datasheet / support / products）。

#### 平台准入判据

- 知网、专利库、百科、标准平台首页等跨领域通用平台不收录（无主题边界）；

- 平台的领域专属入口（分类检索页 / 领域检索页）可收。

#### 粒度规则

- 每条候选标注 granularity：合集级 / 单篇级；

- 同一来源同时有合集入口与单篇时，优先收合集入口。

#### 语言版本偏好

- 同一内容多语言版本只收一个，优先级：中文 > 英文 > 其他。

#### 证据链规则（脚本强制校验）

- 候选 URL 逐字照抄搜索结果；

- 禁止凭先验知识补 URL（须先搜索使 URL 出现在结果中再收录）；

- 禁止规范化（补路径 / 换域名 / 去参数）与截短 URL。

#### 数据源类型标签

- source\_type 从词类词汇（组织形式词 / 体裁词 / 来源角色词）中选取，不另造同义新词。

## 五、设计依据（社区思想借鉴）

- 评审层触发补搜（GPT Researcher）：review 生成缺口清单，缺口触发 plan 补充搜索；

- 计划反思与拆解修订（Deep Researcher Reflect Evolve）：领域结构为可演进的树形结构，搜索发现可反向修订；

- 验证驱动发现（AREX，发现-验证不对称）：收敛判据中的"脚本校验客观覆盖"，使验证不仅拦截错误，还驱动后续发现；

- LLM 完成度判定（Deep Researcher Reflect Evolve）：覆盖充分性判断 `{收敛, 理由}`。
