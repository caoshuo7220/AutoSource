# 参考方案手册

> 用途：外部调研记录——与"数据源发现"相关的同类方案、可复用组件、社区共识模式，及其与 AutoSource 的关系。
> 调研时间：2026-08-14。本手册随调研持续更新。

## 1. 调研结论摘要

1. **没有可直接拿来用的完整方案**——"领域描述 → 泛化数据源清单 + CSV + 确定性后处理"这个目标组合在社区里没有现成实现，最接近的同类工具都只覆盖其中一段
2. **AutoSource 的两路方案被社区共识独立印证**——多个项目在不同场景收敛出相同模式（见第 3 节对照表）
3. **外部 SaaS 组件在当前环境不可达**（实测见第 4 节），内置 WebSearch + 本地脚本仍是唯一可行基础

## 2. 同类方案盘点

### 2.1 关键词 → 资源清单类（目标最接近）

**GPT-Awesome-List-Generator**（github.com/Curated-Awesome-Lists/GPT-Awesome-List-Generator）
- 输入关键词+描述 → GPT 生成 Markdown 资源清单（GitHub 项目、论文、课程、工具等）
- 依赖 OpenAI API + Google Custom Search，~31 star
- 评价：思路同源但粗糙——无分类树、无验证机制、无证据链、无后处理。不可直接用，仅佐证"LLM+搜索生成清单"的可行性

**awesome-list-radar**（GitHub Action，awesome list 自动维护）
- 四阶段管线：收集（GitHub repos/arXiv 论文/博客 RSS）→ 关键词过滤+去重 → **Claude API 结构化推理判定相关性** → **输出 GitHub issue 供维护者人工批准/拒绝**
- 评价：**与 AutoSource"两路发现 + 抽检闭环"几乎同构**。最值得借鉴的是"LLM 判定 + 人工审批 issue"的闭环实现形态。差异：它的收集源是结构化 API（GitHub/arXiv/RSS），我们是通用 web 搜索

**Claude-Resource-List-Builder-Plugin**（github.com/danielrosehill）
- Claude Code 插件：把用户给的已知 URL 列表分类、补元数据、生成 awesome list；含死链审计
- 评价：输入是已知 URL 而非领域描述，与 AutoSource 互补不重叠

### 2.2 研究型 agent（范式最成熟）

**GPT Researcher**（github.com/assafelovic/gpt-researcher，MIT）
- planner/executor 多智能体：规划研究问题 → 并行抓取 → 逐资源摘要（带来源追踪）→ 聚合报告（2,000+ 词、20+ 来源）
- 可插拔检索器：Tavily（默认）/Google/Bing/DuckDuckGo/SearX；抓取用 BeautifulSoup/Playwright；支持 MCP 数据源；LangGraph 编排 + LangSmith 观测
- 评价：可借鉴**检索器抽象、来源追踪、多智能体编排**；不适用：目标是研究报告而非清单，FastAPI+前端框架过重

**Stanford STORM**（github.com/stanford-oval/storm；论文 NAACL 2024 *Assisting in Writing Wikipedia-like Articles From Scratch with LLMs*、EMNLP 2024 Co-STORM）
- 两阶段：预写研究（**Perspective-Guided 提问** + 模拟专家对话）→ 写作，产出带引用的 Wikipedia 风格文章
- 评价：**perspective-guided 提问 = AutoSource"清单自检/完整性自检"的学术版**——从多视角枚举遗漏，机制同构

### 2.3 数据目录 / 元数据收割（数据工程领域）

**CKAN / Magda / DataHub / Alation**（数据目录平台）
- 定位：企业/政府**已知**数据资产的元数据目录与治理（连接器收割、血缘、治理），不是"未知领域源发现"
- 评价：目标不同，不适用；但 DataHub 的 MCP 集成可作未来下游消费参考

**Ceres**（github.com/AndreaBozzo/Ceres，Rust）
- harvest-first 工具包：**维护 300+ 门户连接器**（CKAN/DCAT/Socrata/STAC…），逐门户同步元数据入库，2M+ 数据集索引
- 评价：**"维护门户清单逐门户检索" = AutoSource 通用基础源池的系统化形态**——通用源池未来可演化为"维护一份已知门户清单 + 每领域逐门户检索"，而非只搜通用 web

**Metatron / XCKAN / 超星发现系统**
- 定位类似（数据集门户爬取/联邦目录/学术资源发现），无直接可借鉴增量

### 2.4 中文信源路由（中文互联网场景）

**观澜 Guanlan**（github.com/shenyangs/Guanlan）
- AI Agent 的中文互联网研究与信源路由工具：**信源路由规则（政策→官方媒体、口碑→社区、技术→开发者与 RSS、产业→垂类媒体）**、网页转 Markdown、热榜观察、证据包输出、watch 命令固化为长期雷达
- 评价：**"信源路由" = 知识清单按机构类型枚举的中文互联网版**，是本清单中与 AutoSource 核心机制最接近的中文项目，建议细读其路由规则表（GitHub 被环境网络拦截，需解锁后 clone）

**FirstData MCP**
- "数据界的导航系统"：**静态维护的数据源知识库**，按国家/领域/权威级别筛选数据源，自动生成点击路径级操作指南（search_source → get_source → get_access_guide）
- 评价：印证"权威数据源知识库是核心资产"；对照出两条路线——AutoSource 走**动态生成+搜索验证**，FirstData 走**静态人工维护**，后者可作为质量标杆对照

### 2.5 基础设施组件（可替换 WebSearch/WebFetch 的行业标准件）

**搜索 API**（2026 年对比，AIMultiple 基准 100 查询 LLM 裁判评分）：

| API | 定位 | Agent 得分 | 价格 | 免费层 |
|-----|------|-----------|------|--------|
| Brave | 独立索引、最快最便宜、高量 grounding | 14.89 | ~$5/1K | 2,000 次/月 |
| Exa | 神经语义搜索，发现概念相关内容 | 14.39 | ~$7/1K | 1,000 次/月 |
| Tavily | agent 原生，返回内容+引用，集成最快 | 13.67 | $5-8/1K | 1,000 次/月 |

行业共识：多供应商路由（Tavily 主 + Exa 语义 + Brave 兜底）。**当前环境网络封锁外部服务，暂不可用**；环境开放后是替换内置 WebSearch 的第一候选（Exa 的语义搜索对"发现型"搜索尤其契合）。

**抓取/内容抽取 API**：

| 工具 | 定位 | 价格 |
|------|------|------|
| Jina Reader | URL 前缀 r.jina.ai/ 即返回干净 Markdown，零配置 | 10M tokens 免费 |
| Firecrawl | 全站爬取 + 结构化抽取（schema 驱动），JS 渲染 | ~$16/5K 页 |

若环境开放，**Jina Reader 是"展开挖掘"复活的成本最低路径**（当前已实测不可达，见第 4 节）。

## 3. 社区共识模式 ↔ AutoSource 机制对照

| 社区模式 | 出处 | AutoSource 对应机制 |
|---------|------|-------------------|
| 收集 → 过滤去重 → LLM 判定 → 人工审批 | awesome-list-radar | 两路发现 + 人工抽检闭环（待建） |
| perspective-guided 多视角提问 | STORM 论文 | 完整性自检 / 清单自检 |
| 信源路由（按机构类型定搜索来源） | 观澜 | 知识清单按机构类型枚举 |
| 维护门户清单逐门户检索 | Ceres | 通用基础源池（可演化为门户清单） |
| 检索器可插拔 + 来源追踪 | GPT Researcher | 搜索层抽象（未来）+ 证据链（已落地） |
| 静态权威数据源知识库 | FirstData MCP | 知识清单的动态生成路线对照物 |

## 4. 环境网络实测记录（2026-08-14）

| 目标 | 结果 | 结论 |
|------|------|------|
| WebFetch opencompute.org | 域名验证拦截 | 展开挖掘受限的原始来源 |
| curl opencompute.org | 403（带浏览器 UA 仍 403，Cloudflare） | WAF 拦截 |
| curl github.com | 超时（15s 无响应） | GitHub 不可达，影响 clone 参考项目 |
| curl ieee802.org / trackawesomelist.com | 200 ✓ | 部分站点直连可用 |
| curl r.jina.ai | 超时（20s 无响应） | Jina Reader 不可用，外部 SaaS 路线受阻 |

结论：**当前环境只有"部分站点直连 + 内置 WebSearch"两条信息通道**，架构设计以此为约束；环境变化后按第 2.5 节组件升级。
