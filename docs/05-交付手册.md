# AutoSource 项目交付手册

> 本文档面向接手的 AI/开发者。阅读完本文档后，你应当能够理解项目全貌、当前状态、既有决策的原因，以及下一步该做什么。

## 1. 项目是什么

AutoSource 是一个 **Claude Code Skill**——用户在对话中输入 `/autosource <领域描述>`，Claude 自动完成"领域拆解 → 数据源搜索 → 去重整理 → 导出 CSV"全流程，产出该领域的公开数据源清单。

核心价值：替代人工梳理数据源的工作，把"找数据源"这件事自动化。

```
输入: /autosource 算力服务器
  ↓
产出: outputs/算力服务器_2026-08-13-173232/
      ├── 算力服务器_2026-08-13-173232_数据源清单.csv   ← 唯一交付物（UTF-8 BOM，Excel 直接打开）
      └── 算力服务器_2026-08-13-173232_stats.csv   ← 效果数据（迭代对比用）
```

每条数据源包含 5 个字段：数据源名称、分类路径、数据源类型（内容体裁）、访问地址、简要说明。

## 2. 项目背景与边界

- **用户职责**：只负责"数据源发现与产出"，不关注下游采集链路（采集有另一套 caiji 系统处理）
- **"数据源"的含义**：泛指一切泛化信息载体——官方文档、技术手册、知识库、API 文档、论文、数据集、开源仓库、排行榜、行业标准、技术博客、资讯平台等。**数据集只是其中一类，不应占主导**
- **边界**：不含需账号权限、付费、非公开的私有数据源

## 3. 当前文件结构与职责

```
d:\Myproject\AutoSource\
├── .claude/
│   ├── settings.json                    ← 项目级权限白名单 + 证据留痕 hook（Git 跟踪，分发给使用者）
│   └── skills/
│       ├── autosource/
│       │   ├── SKILL.md                ← 顶层编排层：拆解→调搜索层→整理→导出
│       │   ├── postprocess.py          ← 后处理流水线：证据校验+去重+CSV 导出+stats+清理（LLM 只产 raw.json）
│       │   └── log_tool.py             ← PostToolUse hook 脚本：系统记录搜索证据留痕（模型不可篡改）
│       └── autosource-search/
│           └── SKILL.md                ← 搜索层：逐节点双维度搜索，返回候选清单
├── tests/
│   └── test_postprocess.py             ← 25 个单元测试（后处理流水线 + 证据留痕），全部通过
├── docs/
│   ├── 01-需求文档.md                   ← 需求规格（功能/输出规范/验收标准）
│   ├── 02-搜索方案.md                   ← 两路搜索方案设计（已定稿，待实施）
│   ├── 03-实施计划.md                   ← 架构概览与已完成任务记录
│   ├── 04-问题记录手册.md               ← 问题清单、决策记录与讨论日志
│   ├── 05-交付手册.md                   ← 本文档（交付接手者必读）
│   └── 06-参考方案手册.md               ← 外部调研：同类方案与可复用组件
└── outputs/                            ← 每次运行的产出目录（Git 忽略）
    └── {领域词}_{时间戳}/
        ├── {领域词}_{时间戳}_数据源清单.csv
        └── {领域词}_{时间戳}_stats.csv
```

**分层架构**（参照了用户已有的 caiji 采集系统模式）：

| 层 | 文件 | 职责 |
|----|------|------|
| 编排层 | autosource/SKILL.md | 领域拆解、完整性自检、流程控制、CSV 导出、汇总报告 |
| 搜索层 | autosource-search/SKILL.md | 构造搜索词、执行 web_search、集合页展开、提取候选、覆盖评估 |
| 后处理 | postprocess.py | 确定性流水线：证据校验、时间戳/目录、去重、CSV 导出、stats、清理（LLM 只产 raw.json） |
| 证据留痕 | log_tool.py + settings.json hook | PostToolUse hook 系统记录每次搜索原始结果；脚本校验 URL 必须逐字在留痕中，从结构上杜绝模型编造 URL |

**设计原则：LLM 负责"懂"，脚本负责"确定性的活"。** 推理和判断在 SKILL.md 指令里；时间戳、去重、CSV 编码、stats 统计这些有标准答案的环节全部在 Python 脚本里（04-问题记录手册 P-005 的结论）。LLM 唯一产出的中间产物是 raw.json。

## 4. 关键决策记录（接手必读）

以下是迭代过程中踩坑后形成的决策，**不要轻易推翻**：

| # | 决策 | 原因 |
|---|------|------|
| 1 | 分类层级深度不固定 | 不同领域自然深度不同（金融 4 层、开源框架 2 层），由模型按领域决定 |
| 2 | 数据源类型不预设枚举 | 按"内容体裁"标注（官方文档/数据集/论文等），由模型按实际形态决定 |
| 3 | 每次运行独立时间戳目录 | 同领域多次运行不覆盖，可对比效果 |
| 4 | 领域词由输入提炼（2-6字），不用原始输入做目录名 | 用户可能输入 200 字长句 |
| 5 | 搜索用"发现型关键词"，禁搜产品规格 | 搜"GPU 排名 数据库"能挖出资源集合；搜"H100 规格"只锚定单一产品页 |
| 6 | 厂商/产品名按意图区分 | 禁搜规格参数页，但允许搜文档站/知识库/API 入口（高价值成体系知识源） |
| 7 | 双维度搜索（组织形式 + 体裁入口）× 中英文 | 既拿"整理好的资源集合"，也拿"权威内容入口" |
| 8 | 提取阶段不做数量筛选 | 搜索层返回的全部候选都收录，减法只在去重环节做 |
| 9 | URL 校验已移除 | 校验误杀严重（反爬 403、国内网络超时），当前聚焦搜索问题，校验以后再说 |
| 10 | 每节点统计候选数+体裁分布 | 薄弱节点判定用（数量少 或 体裁单一），写入 stats.csv 供迭代 |
| 11 | 拆解后做完整性自检 | 自问"有没有漏掉的公认子方向"（例：算力服务器补入 ARM/国产处理器） |
| 12 | 权限走 settings.json 项目级分发 | 使用者 clone 后首次确认一次，之后不再弹窗 |
| 13 | CSV 文件名带领域词+时间戳 | 多次运行的清单要能同时打开对比，Excel 不允许打开两个同名文件；文件名自描述，脱离目录也能识别 |
| 14 | 时间戳由脚本生成，模型禁止编造 | 模型没有时钟，曾编出与实际差 3 小时的时间戳；且两次运行若编出相同时间戳会互相覆盖 |
| 15 | stats 输出用 CSV 长表，命名与数据源清单同步 | 原 stats.json 不便在 Excel 查看；CSV 可直接打开、多次运行横向对比，文件名带领域词+时间戳 |
| 16 | 确定性环节全部代码化，LLM 只产 raw.json | 时间戳编造、CSV 转义错误、stats 口径不一致等实测问题均源于 LLM 手工执行确定性步骤；脚本可测试、可复现（P-005 结论） |
| 17 | 证据留痕 + grounding 校验防 URL 编造 | 实测发现候选里混入凭记忆补的 URL（dentOS/Stratum）。指定工具管不住字段级幻觉，提示词约束不可强制；由系统 hook 记录搜索证据、脚本逐字校验 URL，编造从概率问题变成结构上不可能 |

## 6. 已知问题与限制

1. **集合页展开（WebFetch）受网络限制**：搜索层 SKILL.md 里写了展开步骤，但实测 `epoch.ai`、`iotdt.com` 等域名被环境安全策略拦截（"Unable to verify if domain is safe to fetch"）。**这是当前覆盖提升的最大瓶颈**，需解决 WebFetch 域名验证问题或改走其他方式展开
2. **URL 校验已移除**（见决策 9），后续若要恢复需先解决误杀问题（浏览器 UA、放宽超时、白名单域名）
3. **stats.csv 无自动消费端**：目前只供人工对比。caiji 系统有 verify-report 自动回炉闭环，这里还没有
4. **搜索次数上限**：每节点第一轮上限 6 次搜索，防 token 膨胀。更大的领域可能需要调整
5. **证据留痕 hook 在会话重启后生效**：settings.json 的 hook 在会话启动时加载；本会话中修改后需重启会话（或信任项目后新开会话）才会触发。hook 生效前 postprocess 会因"证据留痕不存在"拒绝处理（设计使然，不是缺陷）

## 8. 下一步建议

优先级从高到低：

1. **换 1-2 个差异大的领域验证通用性**（如"数学"、"金融数据"）——验证搜索策略在非硬件领域的表现，这是 AC-6 的要求，也是当前最大的未知
2. **解决 WebFetch 域名验证问题**——集合页展开是覆盖提升的最大杠杆，当前被环境安全策略卡住
3. **考虑跨项目使用场景**——当前 skill 装在项目 .claude/skills 下，如果要在其他项目用，需考虑全局安装或做成 MCP/插件分发
4. **stats.csv 消费闭环**——迭代期手动看，稳定后可考虑像 caiji 一样做自动回炉

```bash
outputs/{领域词}_{时间戳}/{领域词}_{时间戳}_数据源清单.csv   # Excel 打开
outputs/{领域词}_{时间戳}/{领域词}_{时间戳}_stats.csv  # 效果数据（多次运行可横向对比）
```
