# AutoSource 项目交付手册

> 本文档面向接手的 AI/开发者。阅读完本文档后，你应当能够理解项目全貌、当前状态、既有决策的原因，以及下一步该做什么。

## 1. 项目是什么

AutoSource 是一个 **Claude Code Skill**——用户在对话中输入 `/autosource <领域描述>`，Claude 自动完成"领域拆解 → 数据源搜索 → 去重整理 → 导出 CSV"全流程，产出该领域的公开数据源清单。

核心价值：替代人工梳理数据源的工作，把"找数据源"这件事自动化。

```
输入: /autosource 算力服务器
  ↓
产出: outputs/算力服务器_2026-08-13-173232/
      ├── 算力服务器_2026-08-13-173232_数据源清单.csv   ← 交付物（UTF-8 BOM，Excel 直接打开）
      ├── 算力服务器_2026-08-13-173232_stats.csv       ← 交付物（清单统计：每节点条数/体裁分布 + 总计行）
      └── intermediate/                                 ← 排障材料（发现问题时才查）
          ├── 算力服务器_2026-08-13-173232_搜索日志.csv ← 搜索复盘（每次搜索的查询词/提取数）
          ├── 算力服务器_2026-08-13-173232_溯源.csv     ← 数据血缘（正查/反查：结果与收录对应）
          ├── raw_input.json                           ← 输入快照（过滤前全量，调试/复盘）
          └── evidence_log.jsonl                       ← 证据留痕（本运行切片，调试/复盘）
```

每条数据源包含 7 个字段：数据源名称、分类路径、数据源类型（内容体裁）、粒度（合集级/单篇级）、访问地址、简要说明、来源搜索（该 URL 在留痕中首次出现的查询词；多出处见溯源.csv）。

## 2. 项目背景与边界

- **用户职责**：只负责"数据源发现与产出"，不关注下游采集链路（采集有另一套 caiji 系统处理）
- **"数据源"的含义**：泛指一切泛化信息载体——官方文档、技术手册、知识库、API 文档、论文、数据集、开源仓库、排行榜、行业标准、技术博客、资讯平台等。**数据集只是其中一类，不应占主导**
- **边界**：不含需账号权限、付费、非公开的私有数据源
- **通用检索入口（不进清单，供下游自行查用）**：知网 CNKI、Google Patents、维基百科/百度百科、全国标准信息公共服务平台、工标网、万方等跨领域恒定平台，不作为发现结果输出（决策 19）；下游如需按领域补充检索，可自行使用这些入口


**分层架构**（参照了用户已有的 caiji 采集系统模式）：

| 层 | 文件 | 职责 |
|----|------|------|
| Skill | autosource/SKILL.md | 单一线性流程（阶段 0-6）：领域拆解、**知识清单**（权威源按叶节点归类）、完整性自检、**验证搜索**（清单逐项验证）、**增量发现**（双维度×中英文 4 次/节点 + 自由角度中文 2 次）、覆盖评估与扩量、**按契约写入 raw.json**、**收尾执行后处理并输出最终汇总**（无中间停靠点） |
| 后处理 | autosource/scripts/postprocess.py | 确定性流水线：证据校验（被拒条目不进清单，明细见 stdout/计数见 stats）、**清单并入与验证率**、去重、CSV 导出（含来源搜索列）、stats、**搜索日志**、**数据血缘溯源.csv（正查/反查）**、**归档**（交付物在根，排障材料入 intermediate/）、清理（raw.json 由流程写入） |
| 证据留痕 | autosource/scripts/log_tool.py + settings.json hook | PostToolUse hook 系统记录每次搜索原始结果；脚本校验 URL 与查询词必须逐字在留痕中，从结构上杜绝模型编造 |

**设计原则：LLM 负责"懂"，脚本负责"确定性的活"。** 推理和判断在 SKILL.md 指令里；时间戳、去重、CSV 编码、stats 统计这些有标准答案的环节全部在 Python 脚本里（04-问题记录手册 P-005 的结论）。raw.json 由流程直接落盘（Write 直落、零转录）。

## 4. 关键决策记录（接手必读）

以下是迭代过程中踩坑后形成的决策，**不要轻易推翻**：

| # | 决策 | 原因 |
|---|------|------|
| 1 | 分类层级深度不固定 | 不同领域自然深度不同（金融 4 层、开源框架 2 层），由模型按领域决定 |
| 2 | 数据源类型不预设枚举 | 按"内容体裁"标注（官方文档/数据集/论文等），由模型按实际形态决定 |
| 3 | 每次运行独立时间戳目录 | 同领域多次运行不覆盖，可对比效果 |
| 4 | 领域词由输入提炼（2-6字），不用原始输入做目录名 | 用户可能输入 200 字长句 |
| 5 | 搜索用"发现型关键词"，禁搜产品规格 | 搜"GPU 排名 数据库"能挖出资源集合；搜"H100 规格"只锚定单一产品页 |
| 6 | 厂商/产品名按意图区分 | 禁搜规格参数页，但允许搜文档站/知识库/API 入口（高价值成体系知识源） |
| 7 | 双维度搜索（组织形式 + 体裁入口）× 中英文 | 既拿"整理好的资源集合"，也拿"权威内容入口" |
| 8 | 提取阶段不做数量筛选 | 提取阶段返回的全部候选都收录，减法只在去重环节做 |
| 9 | URL 校验已移除 | 校验误杀严重（反爬 403、国内网络超时），当前聚焦搜索问题，校验以后再说 |
| 10 | 每节点统计候选数+体裁分布 | 薄弱节点判定用（数量少 或 体裁单一），写入 stats.csv 供迭代 |
| 11 | 拆解后做完整性自检 | 自问"有没有漏掉的公认子方向"（例：算力服务器补入 ARM/国产处理器） |
| 12 | 权限走 settings.json 项目级分发 | 使用者 clone 后首次确认一次，之后不再弹窗；2026-08-18 起运行期/开发期分层——settings.json 只留流水线最小集（搜索/读/outputs 读写/postprocess 规则），开发期便利项（python -c/pip install/git 等）在 settings.local.json（gitignore，不分发） |
| 13 | CSV 文件名带领域词+时间戳 | 多次运行的清单要能同时打开对比，Excel 不允许打开两个同名文件；文件名自描述，脱离目录也能识别 |
| 14 | 时间戳由脚本生成，模型禁止编造 | 模型没有时钟，曾编出与实际差 3 小时的时间戳；且两次运行若编出相同时间戳会互相覆盖 |
| 15 | stats 输出用 CSV 长表，命名与数据源清单同步 | 原 stats.json 不便在 Excel 查看；CSV 可直接打开、多次运行横向对比，文件名带领域词+时间戳。2026-08-21 起瘦身为纯清单统计表：分类节点/候选数/体裁分布每节点一行 + 末尾"总计"行；运行级信息在文件名（领域/时间戳）、raw_input.json（模型）、stdout（过程健康指标） |
| 16 | 确定性环节全部代码化，LLM 只产 raw.json | 时间戳编造、CSV 转义错误、stats 口径不一致等实测问题均源于 LLM 手工执行确定性步骤；脚本可测试、可复现（P-005 结论）。2026-08-20 补强：raw.json 改由搜索层直接落盘、编排层零文件写入（build_raw.py 事件——编排层自创脚本组装大 JSON 触发弹窗，证明组装本身是确定性环节，归位） |
| 17 | 证据留痕 + grounding 校验防 URL 编造 | 实测发现候选里混入凭记忆补的 URL（dentOS/Stratum）。指定工具管不住字段级幻觉，提示词约束不可强制；由系统 hook 记录搜索证据、脚本逐字校验 URL（2026-08-18 起为边界匹配，截短为父路径/裸域名不放行），意外编造从概率问题变成结构上杜绝（留痕文件无写保护，不防对抗性篡改） |
| 18 | 两路发现：知识清单 + 验证搜索 + 增量发现 | 单路搜索无法保证"该有的都有"——先由领域知识点名权威源（URL 留空）、搜索验证（幻觉被挡在未验证清单）、再增量补充；清单验证是自洽性指标不衡量完整性。展开挖掘整体抛去（D3）。详见 02-搜索方案.md |
| 19 | 通用平台不作为独立条目 | 实测清单混入知网/Google Patents/标准平台等跨领域通用平台——无主题边界（违反 P-002）、平台首页 URL 下游采集不到领域内容、人尽皆知纯噪声。判据：条目 URL 必须定位到该领域的内容；平台信息通过领域条目描述传递；跨领域恒定入口写在本手册第 2 节供下游自行查用 |
| 20 | 粒度矛盾脚本检测 | 曾实施后按用户决策**移除**（2026-08-20）：产量优先、粒度/子站问题由后续"站点与子站合并"功能处理；granularity 声明保留为信息展示（清单"粒度"列 + 单篇级收录计数），不再拒绝 |
| 21 | 单 skill 合并（skill 规范） | 2026-08-24 按 skill-creator 规范评审：skill 的设计单位是"用户意图触发的工作流"，搜索/验证/提取/后处理是同一工作流内部阶段，独立子 skill 触发面为空、违反"description 承载 when-to-use"的设计。合并为单一 autosource skill（SKILL.md 线性流程 阶段 0-6），脚本归位 scripts/；收尾仍为最后一步，无中间停靠点不变 |

## 6. 已知问题与限制

1. **集合页展开（WebFetch）已从流程移除**（两路方案决策 D3，2026-08-14）：搜索富摘要已承担部分展开价值、当前主要矛盾是质量而非数量、环境域名验证受限。若未来需要长尾覆盖，可作为可选增强恢复（curl 对部分站点可用，见 06-参考方案手册第 4 节实测记录）
2. **URL 校验已移除**（见决策 9），后续若要恢复需先解决误杀问题（浏览器 UA、放宽超时、白名单域名）
3. **stats.csv 无自动消费端**：目前只供人工对比。caiji 系统有 verify-report 自动回炉闭环，这里还没有
4. **搜索量预算**：单次运行约 130 次搜索（验证 ≤50 + 增量发现 4 次/节点 + 扩量 ≤2 轮，见 02-搜索方案.md 预算节），属有意为之的质量成本；若实测过重，优先砍扩量轮的补搜
5. **证据留痕 hook 在会话重启后生效**：settings.json 的 hook 在会话启动时加载；本会话中修改后需重启会话（或信任项目后新开会话）才会触发。hook 生效前 postprocess 会因"证据留痕不存在"拒绝处理（设计使然，不是缺陷）

## 9. 使用说明

```bash
# 基本用法
/autosource 算力服务器

# 带约束
/autosource 算力服务器 -c "GPU服务器" "CPU服务器"

# 运行后检查
outputs/{领域词}_{时间戳}/{领域词}_{时间戳}_数据源清单.csv   # 交付物，Excel 打开
outputs/{领域词}_{时间戳}/{领域词}_{时间戳}_stats.csv        # 交付物，清单统计（每节点条数/体裁分布 + 总计行）
outputs/{领域词}_{时间戳}/intermediate/{领域词}_{时间戳}_搜索日志.csv      # 排障：搜索复盘（每次搜索的查询词/提取数）
outputs/{领域词}_{时间戳}/intermediate/{领域词}_{时间戳}_溯源.csv          # 排障：数据血缘（按查询词/条目名称筛选，正查/反查；"返回结果数"来自 journal 约数、结果行数为证据真实数；"节点"为搜索发生处，顺路发现的源可能跨节点归因）
outputs/{领域词}_{时间戳}/intermediate/raw_input.json        # 排障：输入快照（过滤前全量，调试/复盘）
outputs/{领域词}_{时间戳}/intermediate/evidence_log.jsonl    # 排障：证据留痕（本运行切片，调试/复盘）
```
