# 搜索方案（两路发现）

> 状态：**已定稿并已实施（2026-08-14）**。
> 关联：证据链（决策 17，已落地）解决"URL 编造"；本方案解决"该有的有没有"——即 04-问题记录手册 P-004/P-008 的质量维度。外部同类方案与社区共识模式对照见 [06-参考方案手册](06-参考方案手册.md)。

## 1. 背景与问题

现状是单路搜索：拆解 → 每个叶子节点双维度×中英文搜索 → 覆盖评估 → 薄弱节点扩量。两次实测暴露的质量缺陷：

- 交换机领域 78 条中 81% 为英文站点，中文权威源（华为/H3C/国标库/知网）随机缺失
- 候选混入凭模型记忆补写的 URL（dentOS、Stratum 事件）——证据链已解决
- 覆盖评估只看数量和体裁，从不核对"领域公认的权威源找到了没有"
- 单路浅层发现（搜索引擎 top-10 + 一次性判断）够不上"数据源发现"的质量门槛

结论：**搜索不应是唯一的发现手段**——先由领域知识点名"该有什么"，搜索负责"验证点名对不对 + 补充没点到的"，权威源核对保证底线。

**展开挖掘（WebFetch 集合页展开）已抛去，不做**，原因：搜索工具的富摘要已天然承担部分展开价值（71/78 条均来自纯搜索）；当前主要矛盾是质量不是数量；环境域名验证受限投入产出比差；下游要的是"点名权威入口"而非穷举长尾。未来环境允许时可作为可选增强恢复。

## 2. 方案总览

```
① 领域拆解（现状保留）
② 知识清单（新增）：LLM 凭领域知识列出公认权威源，按叶节点归类，URL 留空
③ 验证搜索（新增）：清单每项一次定向搜索，URL 出现即验证通过并照抄
④ 增量发现（现状保留）：双维度×中英文 4 次 + 自由角度中文 2 次，找清单之外的源
```

- **知识负责"知道有什么"，搜索负责"证明地址是对的"**——与证据链天然衔接：验证通过的 URL 必在搜索结果里，必过 grounding 校验
- 语言生态不设专门机制：中文权威源（华为/H3C/锐捷/国标/知网）本来就躺在模型知识里，清单列出来、验证搜索自然命中

## 3. 流程设计

### 阶段 1 · 知识清单（拆解后，零搜索）

- 时机：拆解完成、开始搜索之前
- 结构：`{名称, 所属叶子节点, 预期体裁}`，**URL 留空待验证**（知识可能记错 URL，这正是 dentOS 事件的教训）
- 规模：**尽量列全、不设上限**（2026-08-21 修订，产量优先；验证不通过的条目由"未找到官方入口"处置自然过滤，无需以搜索成本为由缩减清单——2026-08-25 修订，原"列杂的代价只是多几次验证搜索"成本措辞删除）；领域级权威源（IETF、Tolly 等）归到最相关节点名下
- 清单条目粒度：**合集级与单篇级都可列**（2026-08-21 修订）——合集级列机构/知识体系；公认的权威单篇载体（白皮书/关键标准文件/重磅报告）可列并声明 granularity
- **清单自检**：列完后按机构类型维度自问一轮——标准组织 / 行业协会 / 厂商文档体系 / 学术文献库 / 评测机构 / 开源生态 / 百科知识库 / 公共数据平台，以及中文生态的对应物，各类都列了吗？有遗漏再补
- 预期体裁仅用于构造验证搜索词；最终 `source_type` 以验证/提取时的实际形态为准，允许修正清单预期
- 交换机示例：

```
数据中心交换机: Cisco Nexus 文档体系、华为 CloudEngine 文档体系、Gartner Peer Insights
企业园区交换机: H3C 配置指南体系、华为 CloudCampus 方案、Cisco Design Zone
工业交换机:     Hirschmann 手册、MOXA 文档、GB/T 30094 国标
以太网标准:     IEEE 802.3 工作组、IEEE 802.1 工作组、全国标准信息公共服务平台
交换芯片:       Broadcom 官网、盛科通信、TechInsights
网络操作系统:   Arista EOS 文档、Cumulus 文档
白盒交换机:     OCP、ONIE、Edgecore
开源NOS:        SONiC 官方文档、ONL
测试与评测:     Tolly、IETF RFC 2544/2889（领域级归此节点）
```

### 阶段 2 · 验证搜索

- 清单每项一次定向搜索（按来源语言中英文；2026-08-24 起改为组件池自由组合，原固定模板 `{机构/体系名} 官方文档 / 官网` 废止为扩量轮兜底角度）：查询词按来源实际情况自由组合（每词 2-4 个组件）——来源识别（必带其一）：原名 / 英文名 / 缩写 / 别名；入口意图：官方文档 / 官网 / 入口 / 目录 / 数据库 / 标准列表 / 仓库；辅助：领域词、地域词和语言词；来源语言不明或双语时，一个查询词内可同时带原名+英文名（如 `宁德时代 CATL 官网`），一次搜索覆盖两种语言（2026-08-25 增补）。首轮优先"来源识别 + 官网 / 官方文档"（2026-08-27 起，首轮 42% 落空实证），落空即标记未验证、留扩量轮换角度。示例：`中国电子技术标准化研究院 交换机 标准`、`IEEE 802.3 Ethernet Working Group official`、`SONiC open source networking documentation`
- **通过标准（2026-08-21 修订：按条目粒度对应，搜到什么按什么收）**：
  - 合集级清单项：搜索结果中出现该机构的**入口 URL**（文档门户/目录/列表页）即通过
  - 合集级清单项只搜到合集内**单篇载体**（PDF、单条 KB 等）：扩量轮换角度专找入口（如 `{机构名} documentation`）；仍找不到入口 → **以该单篇验证通过**，granularity 修正为"单篇级"，reason 注明"仅找到单篇载体，未找到合集入口"
  - 单篇级清单项：搜索结果中出现**该载体本身**即通过
  - 连单篇载体都没有 → "未找到官方入口"
- 通过后：在**清单项内**填上 URL/体裁/描述/收录理由（脚本会自动并入 sources，LLM 无需在 sources 里重复写清单条目），证据链自动满足
- **第一轮每项只搜 1 次**：失败即标记未验证，不在本阶段重试——换角度重试统一留给扩量轮（见阶段 4）
- **未验证分两类处置**（扩量轮换角度重试后定案）：
  - 疑似幻觉/过时：换角度重试后仍搜不到该机构存在的任何证据 → 从有效来源中剔除，报告标注“疑似无效机构”
  - 疑似搜索词问题：能搜到该机构存在、但始终找不到官方入口 → 扩量轮结束仍失败 → 留在未验证清单，标记"未找到官方入口"
- 验证搜索顺路发现的新源 → 全量提取（同样遵守粒度规则与证据链约束）

### 阶段 3 · 增量发现（现有逻辑压缩）

- 每节点 **12 次**（2026-08-27 起 8→12 增产改造）：**固定 4 次**（组织形式词中/英 + 体裁词中/英，各取最贴节点的一个词）+ **自由 8 次**（仅中文，从角度池任选本节点未覆盖的 8 个角度各搜一次，优先覆盖不同的来源类型与来源角色、避免同类角度重复换词；角度池：列表/排名/数据库/标准/仓库/合集、官方文档/手册/知识库/白皮书/论文、数据集/开放数据、社区/博客/资讯平台、论文/专利、标准组织/监管机构/政府部门/行业协会/厂商/研究机构/大学/评测机构/基金会/公共数据平台）。搜索词必须带发现型词汇，厂商/产品名的用法同 SKILL.md 通用纪律“搜索词构造”；易失效角度规则（论文/专利/标准及英文裸后缀 `X list` 必须组合入口词，2026-08-27 实证裸搜命中垃圾页/通用平台首页）见 SKILL.md 阶段 3。提取端“逐条判断、禁止整行拒收”（2026-08-27 Nokia 事件实证：10 条官方文档页整行被放跑）见 SKILL.md 通用纪律提取规则
- 全量提取、URL 逐字照抄（证据链约束不变）
- **数据源类型标签**（2026-08-26 起）：`source_type` 从词类词汇中选取，组合仅限词类词汇两两拼合（不加领域名）、同义新词禁止——历次运行标签 12-92 类波动的治理
- **粒度规则（声明为信息展示，脚本不拦截——2026-08-20 修订；2026-08-21 再修订：单篇也提取）**：
  - 每条候选声明 `granularity`：**合集级**（默认）/ **单篇级**——仅作信息标注（后续站点/子站合并功能会用到），脚本不据此拒绝任何条目
  - 单篇内容同样提取（标单篇级、reason 写明依据）——单篇级不再是例外（2026-08-21 起，合并功能暂缓但提取放开）；同来源有合集入口时优先收入口防重复
  - 仍然不收的只有：与领域无关的噪声、通用平台首页、已收录重复
  - **语言版本偏好**：同一内容多语言版本并存时按 中文 > 英文 > 其他 只收一个；脚本以确定性审计兜底（同域名剥语言码路径段后相同的组计数，见 stats"多语言版本并存组"列，只计数不自动合并）

### 阶段 4 · 覆盖评估与收敛

每节点除候选数与体裁外，按 6 个核心来源维度核对覆盖情况（官方组织与标准 / 厂商与产品生态 / 学术与研究 / 开源与社区 / 数据集与公共数据 / 行业协会与市场信息）。薄弱节点判定标准：

| 情形 | 判定 |
|------|------|
| 候选少 + 清单项有未验证 | **薄弱**——扩量轮优先把未验证清单项验证掉（每轮换一个角度：中英切换 / 全称缩写别名 / `机构名+官网`，见阶段 2），而非无目标的泛搜 |
| 候选少 + 清单项全验证通过 | **不薄弱**——权威源就这些，硬扩只会引入长尾噪声 |
| 体裁单一 | **薄弱**（判定不变） |
| 来源维度单一（条目明显集中于一个维度，如全是厂商文档；2026-08-24 起） | **薄弱**——扩量轮按空缺维度定向补搜（用来源角色词构造查询）；空缺维度对该节点明显不适用时（如纯标准节点只有标准组织）不补 |

"候选少"的阈值沿用现状口径：0 条，或明显少于同级节点。

终止条件：所有节点非薄弱或已收敛 且 清单项全部了结（验证通过或已定案）。**扩量轮按节点独立判断（2026-08-27 起，原"全局 2 轮"废止）**——仍薄弱的节点继续扩量、非薄弱节点停止；某节点连续一轮无任何新增有效来源时视为收敛并停止、如实报告，避免无限循环。

扩量轮内的搜索范围：① 未验证清单项换角度验证；② 体裁单一的节点换体裁词补搜（每轮 ≤4 次）；③ 来源维度单一的节点按空缺维度补搜（每轮 ≤4 次）。除这三类外不做其他补搜。

### 接口契约（阶段间数据传递，2026-08-24 起为单 skill 内部流转）

**阶段 0/1 产出 → 搜索阶段的输入**：
- `nodes`：叶子节点列表
- `knowledge`：权威源清单（含 name / node / 预期体裁；verified 默认 false，url 留空）
- `domain`（领域词）与 `model`（模型名）：照抄进 raw.json

**输出**（2026-08-20 起落盘契约，原"文本返回"废止）：
- 流程开始时运行 `postprocess.py --prepare` 预留唯一运行目录 `outputs/run_{时间戳}/`（2026-08-24 起：契约冲突治理——旧固定路径 `outputs/raw.json` 在连续/并发运行时会互相覆盖，且前文声明的时间戳目录与固定路径矛盾）
- 阶段 5 按契约把 raw.json 写入预留目录（Write 工具）：`domain / nodes / model / knowledge / sources / journal`（build_raw.py 事件后组装环节归位——raw.json 由流程直接落盘、零转录）
- **收尾**（2026-08-21 起）：把预留目录路径传给 postprocess——脚本将其重命名为 `outputs/{领域词}_{时间戳}/`、raw.json 归档进 intermediate/，并把 stdout 作为最终汇总输出——平板轮实测"文本交接"断点（报完状态即停，后处理无人执行），修法是把收尾写进流程最后一条指令，运行到收尾才算结束
- 失败路径：不写 raw.json、不运行后处理，文本返回 `failed: true`；预留目录残留为空（可见可删）

### 失败路径与降级

- **清单为空**（模型对该领域知识空白）：退化为纯增量模式（阶段 3 照常执行），报告标注"知识清单为空，本次无底线保证"；脚本记清单验证 0/0
- **搜索工具持续异常**（验证搜索大面积失败）：中止并如实报告，不产出空 CSV；raw.json 保留供人工检查
- **knowledge 缺失/结构损坏**：脚本警告并记 0/0，不阻断（兼容纯增量模式）

## 4. 产出变化

- **汇总报告**增加：`清单核对: 验证通过 X/Y 项` + 未验证清单列表（**人工交接单**：供人工确认真实后自行处理，不进 CSV）
- **搜索日志**：新增 `{领域词}_{时间戳}_搜索日志.csv`——每行一次搜索（阶段/节点/查询词/返回链接数/提取候选数），供人工复盘"搜了什么、搜到了多少"。查询词在 raw.json 的 `journal` 字段记录；脚本校验每个查询词必须逐字出现在证据留痕中（不在 → 该行"证据缺失"列标注），并写 CSV（UTF-8 BOM，与数据源清单/stats 同编码同命名模式）
- **stats CSV**（2026-08-21 起为纯清单统计表）：每行一个分类节点（分类节点/候选数/体裁分布），末尾一行"总计"；运行级指标（清单验证等）仅在 stdout 汇总，不落 stats
- **数据源清单 CSV** 增加列：`粒度`（合集级/单篇级，供人工按粒度抽检）
- **指标性质（重要）**：`清单验证` 衡量的是**清单自洽性**（模型列的清单里验证通过了几项）——反映幻觉/过时信号与流程稳定性，**不衡量对真实世界的完整性**。完整性评估属 P-004（2026-08-18 结案：零人力约束下外部基准不成立，见 04-问题记录手册），本指标不承担完整性测量
- **领域分析报告**（2026-08-25 起）：收尾最后一步按模板 Write 第三交付物 `分析报告.md`——数据源是输入、领域洞察是产出（概览/技术格局/产业生态/标准体系/中外对比/趋势观察六板块）；模板在 references/分析报告模板.md（progressive disclosure，SKILL.md 只留指针）；依据锚定 + 免责声明防模型空谈；报告为模型产物，脚本零改动
- **raw.json** schema 增加 `knowledge` 字段：

```json
{
  "domain": "交换机",
  "nodes": [...],
  "knowledge": [
    {"name": "IEEE 802.3 以太网工作组", "node": "以太网标准(IEEE 802.3)", "verified": true,
     "category_path": "交换机-核心技术-以太网标准(IEEE 802.3)",
     "source_type": "行业标准", "url": "https://www.ieee802.org/3/",
     "description": "IEEE 以太网标准工作组官网", "reason": "清单验证通过，官方入口"},
    {"name": "某某机构", "node": "某节点", "verified": false, "note": "未找到官方入口"}
  ],
  "journal": [
    {"phase": "验证搜索", "node": "以太网标准(IEEE 802.3)", "query": "IEEE 802.3 Ethernet Working Group official", "results": 10, "extracted": 3}
  ],
  "sources": [...仅增量发现条目...]
}
```

**脚本自动合并**：`verified=true 且带 name/url` 的清单项由脚本自动并入 `sources`（verified 项需带齐 `category_path/source_type/url/description/reason`，缺 name/url 的脚本告警计数；LLM 不手工复制，消除"标了 verified 却漏写条目"的一致性风险）。脚本计算清单验证率为 `verified 且 name/url 均非空的项数 / 总数`（分母仅统计 dict 条目；自洽性指标，性质见上）。`knowledge` 缺失时脚本警告并记 `0/0`，不阻断（兼容纯增量模式）。

`sources` 每条含：`name / category_path / source_type / granularity / url / description / reason`（`reason` 为收录理由，粒度判定可审计；`granularity` ∈ 合集级/单篇级）。
