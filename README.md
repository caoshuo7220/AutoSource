# AutoSource

> 输入一句领域描述，自动产出一份可溯源的公开数据源清单。

AutoSource 是一个 [Claude Code](https://claude.com/claude-code) Skill。它把一个领域的公开数据源发现过程——**领域拆解 → 知识清单 → 逐个验证 → 增量发现 → 覆盖评估 → 收尾导出**——变成一条可重复执行的流水线，产出结构化清单与领域分析报告。

```
/autosource 交换机
```

---

## 它解决什么问题

给一个技术领域，找出该领域值得长期跟踪的数据源（官方文档、标准库、论文库、行业报告、厂商资料站、测试机构、数据集……），这件事目前只有两种做法：

| 做法 | 问题 |
|---|---|
| 人工搜集 | 慢；结果取决于个人经验；换个人、换一次，结果不一致；无法复盘"当时为什么没收这条" |
| 直接问大模型 | 快，但会编造 URL；来源不可查；同一问题两次答案不同；无法审计 |

AutoSource 的思路是**把这两条路的优点拼起来**：让 LLM 只做它擅长的语义判断（怎么拆解领域、这条结果算不算数据源），把一切确定性的环节交给脚本（URL 校验、去重、分类、统计、落盘、收尾对账）——并且**让脚本在客观矛盾出现时拦住 LLM**，而不是靠提示词里写一句"请不要编造"。

---

## 特性

- **证据链**：候选 URL 必须逐字出现在系统记录的工具调用留痕中，脚本逐条校验，找不到的当场拒绝。防的是"凭印象补 URL"这类模型幻觉——提示词约束不住它，但留痕比对能。
- **行级溯源**：交付清单里每条来源都能反查"出自哪次搜索"，`溯源.csv` 记录每次搜索返回了什么、收录了哪几条。
- **收尾护栏**：搜索次数不足、零提取未写理由、声称已收录但域名对不上等**客观矛盾**会在收尾时拒绝并点名；语义判断（值不值得收）不拦——那拦不住，只会逼出敷衍。
- **不改数据也编不出数据**：数据落盘只走 MCP 工具，模型没有直接写数据文件的权限。
- **全过程可复盘**：搜索日志、统计、血缘、证据留痕随产物一起归档。

## 工作原理

```
初始化（预留运行目录）
  → 0 领域拆解      把领域拆成树状节点，每个叶子节点写搜索画像
  → 1 知识清单      零搜索，凭领域知识列出该领域已知的权威来源（URL 留空待验证）
  → 2 验证搜索      逐个验证清单项，找到官方入口即通过，找不到当场记"未验证"
  → 3 增量发现      每节点固定 20 次搜索（固定 4 + 自由 8 + 实体 4 + 扩充 4）
  → 4 覆盖评估与扩量 按来源维度判薄弱节点，对薄弱节点定向补搜，未验证项在此定案
  → 5 清单核对自检   对账"清单声明 N 项"与"实际核对 N 项"
  → 6 收尾          折叠为交付物，写分析报告
```

流程中间没有交接停靠点，跑完才算结束。

## 架构

```
Skill      .claude/skills/autosource/SKILL.md                流程定义（模型读的）
MCP 服务   .claude/skills/autosource/scripts/mcp_server.py   五个工具，会话自动拉起（.mcp.json 注册）
存储层     .claude/skills/autosource/scripts/store.py        store.jsonl 追加日志 + 入库即验
后处理     .claude/skills/autosource/scripts/postprocess.py  流水线编排（校验/去重/CSV/stats/收尾）
           ├── evidence.py   证据链：留痕定位、边界匹配、锚点清理
           ├── lineage.py    血缘：溯源表与"来源搜索"列归因
           └── report.py     报告：数据总览注入与命名
证据 hook  .claude/skills/autosource/scripts/evidence_hook.py PostToolUse hook，系统记录搜索留痕
```

**五个 MCP 工具**（模型唯一的写数据通道）：

| 工具 | 用途 |
|---|---|
| `record_sources` | 新增数据源条目入库（URL 逐条过证据链校验） |
| `record_search` | 搜索日志入库 |
| `record_knowledge` | 知识清单的核对结果入库 |
| `coverage` | 查每个节点"已收"与"提取"的缺口（只读） |
| `finalize` | 收尾折叠，一次产出全部交付物 |

## 设计原则

**LLM 只负责语义，确定性环节全部脚本化。**

- 语义（模型判断）：领域怎么拆、这条结果算不算数据源、未验证项该不该剔除
- 确定性（脚本保证）：时间戳、目录命名、URL 校验、分类归属、去重、统计、编码、收尾对账、文件清理

这条分工带来两个直接后果：**模型没有写数据文件的权限**（只能通过 MCP 工具入库，单次写入上限约一个节点批次，写截断在机制上不可能发生）；**模型编造的 URL 进不了清单**（留痕比对是脚本做的，模型不参与）。

**关于"加约束"**：这个项目反复验证过一条经验——写在提示词里的约束拦不住模型，只有能被脚本判定的**客观矛盾**才拦得住。所以护栏只加在客观矛盾上（URL 不在留痕、归不到节点、日志少于证据、域名在垃圾域名单），语义判断一律不拦。这条经验来自真实事故复盘，不是设计洁癖。

---

## 已知边界

- **完整性无法量化**。没有人力基准的情况下，"这个领域的数据源找全了没有"没有客观答案。本项目提供的是**通道多样性**信号（覆盖了哪几类来源角色），不是召回率保证。
- **不抓取网页内容**。全程只做检索与登记——搜索结果由宿主提供的搜索工具返回，AutoSource 不访问、不下载目标站点。
- **结果质量受底层搜索工具影响**。搜索结果会返回 CDN/镜像主机名、带跟踪参数的 URL 等，脚本能做形态审计与名单过滤，但无法判断一个具体链接是否已失效。
- **成本与耗时**。一次运行约 200–350 次搜索，耗时二三十分钟，产出数百条条目。
- **依赖 Claude Code 的 hook 机制**。证据链由 PostToolUse hook 实现，迁移到其他宿主需要自行实现等价的留痕机制。

## 项目结构

```
.claude/skills/autosource/   Skill 本体（流程定义 + 脚本）
.claude/settings.json        权限白名单与 hook 配置
.mcp.json                    MCP 服务注册
tests/                       单元测试
```

### 权限与 hook

- `settings.json` 定义流水线所需的最小权限集：运行期只放行搜索、Read、Write（仅 `outputs/`）、五个 MCP 工具，以及两条固定的 postprocess 命令（初始化运行目录、报告改名）——正常情况下零弹窗。白名单是命令注入的唯一防线，因此刻意保持最小。
- `evidence_hook.py` 注册为 PostToolUse hook，拦截 `WebSearch` / `WebFetch`，把工具调用的原始输入输出追加到运行目录的留痕文件。**留痕由宿主记录，模型无法选择记什么**——这是证据链成立的前提。
