# AutoSource — 数据源自动发现

当用户输入 `/autosource <领域描述>` 时，执行以下流程。

**分工原则**：LLM 只负责语义环节（领域拆解、知识清单、搜索、验证与提取判断），一切确定性环节（时间戳、目录命名、证据校验、清单并入、去重、CSV 编码、stats 统计、搜索日志、文件清理）由脚本保证。LLM 唯一需要产出的中间产物是 `raw.json`——写完它之后调用脚本即可，**不得手工代做脚本的活**。

**证据链**：每次 WebSearch/WebFetch 的原始结果由系统 hook 自动记录到 `outputs/search_log.jsonl`（PostToolUse hook，模型不可篡改）。脚本校验 raw.json 里每个候选 URL 与搜索日志的每个查询词必须能**逐字**在证据留痕中找到，否则拒绝/标注。因此：**所有候选 URL 必须逐字照抄搜索结果；凭先验知识补的 URL 必须先补一次搜索、出现在结果里才能收录；journal 的查询词照抄实际发出的查询词。**

- **领域词**：从用户输入的领域描述中提炼，取核心关键词（2-6 字），空格替换为 `_`，写入 raw.json 的 domain 字段。
- **输出目录**：脚本用自身系统时钟生成 `outputs/{领域词}_{时间戳}/`，LLM 不参与目录命名。

示例：输入 `帮我收集用于AI训练的GPU算力服务器相关数据源` → 目录 `outputs/算力服务器_2026-08-12-143000/`。

## 参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `<领域描述>` | 是 | 粗粒度文本，如 `算力服务器` |
| `-c` | 否 | 预设分类路径，如 `-c "GPU服务器" "CPU服务器"` |
| `-t` | 否 | 限定数据源类型，如 `-t "数据集" "产品文档"` |

## 执行流程

### 1. 领域拆解（用户未指定 -c 时执行）

将领域拆解为树状分类结构。遵循以下原则：

- 层级清晰：上下级严格包含，同级互斥不重叠
- 符合领域常识：分类体系与该领域公认知识体系一致
- 符合业务逻辑：粒度匹配实际使用场景，不过细也不过粗
- 深度自适应：不同领域层级数可不同（如金融可能 4 层，开源框架可能 2 层）
- 覆盖完整：覆盖该领域主要方向，无明显遗漏

**完整性自检**：初步拆解后，再自问一遍——"这个领域公认的主要子方向，有没有被遗漏的？"显式列出可能被漏掉的方向（某个细分技术、某类应用场景、某个层级），对照领域常识决定是否补入，再定稿。

将拆解结果以树形文字展示给用户。

### 2. 知识清单（拆解完成后，零搜索）

基于领域知识直接列出该领域公认的**权威源清单**，不花一次搜索：

- 结构：`{名称, 所属叶子节点, 预期体裁}`，**URL 留空待验证**（知识可能记错 URL）
- 规模：每叶节点 2-5 条（不含领域级条目）；领域级权威源（IETF、Tolly 等）归到最相关节点名下；总量 ≤50
- 清单条目粒度均为"体系级"
- **清单自检**：列完后按机构类型维度自问一轮——标准组织 / 行业协会 / 厂商文档体系 / 学术文献库 / 评测机构 / 开源生态 / 百科知识库 / 公共数据平台，以及中文生态的对应物，各类都列了吗？有遗漏再补
- 预期体裁仅用于构造验证搜索词；最终 `source_type` 以验证时的实际形态为准，允许修正

将清单与分类树一起展示给用户。

### 3. 数据源搜索

调用搜索层 `/autosource-search`，传入**叶子节点 + 权威源清单**。搜索层负责：

- **验证搜索**（阶段 1）：清单每项一次定向搜索；通过的在清单项内填上 URL/体裁/描述/收录理由；失败的在扩量轮换角度重试后按两类定案（疑似幻觉→剔除标注；搜索词问题→留在未验证清单标注"已尽力"）
- **增量发现**（阶段 2）：每节点双维度×中英文 4 次搜索，找清单之外的源；粒度规则：默认合集级，站点/单篇仅例外（判定话术见搜索层）
- **覆盖评估与扩量**（阶段 3）：薄弱判定新标准（候选少+清单未验证→扩量优先验证清单项；候选少+清单全验证→不薄弱；体裁单一→薄弱），终止条件含清单收敛
- 返回：验证后的清单 + 增量候选 + 搜索日志 journal（搜索工具大面积失败时返回 `failed: true`，见搜索层失败路径）

**失败处置**：搜索层返回 `failed: true` 时**中止流程**——不写 raw.json、不调用后处理，如实向用户报告"搜索工具异常，本次运行中止"。

等待搜索层返回后进行下一步。

### 4. 结果整理 → 写 raw.json

把搜索层返回的结果写入 `outputs/raw.json`（固定路径，脚本处理完成后自动删除）。**写入映射：knowledge 原样写入 `knowledge` 字段，new_sources 写入 `sources` 字段，journal 原样写入 `journal` 字段。**

```json
{
  "domain": "交换机",
  "nodes": ["数据中心交换机", "以太网标准(IEEE 802.3)", "..."],
  "model": "当前使用的模型名",
  "knowledge": [
    {"name": "IEEE 802.3 以太网工作组", "node": "以太网标准(IEEE 802.3)", "verified": true,
     "category_path": "交换机-核心技术-以太网标准(IEEE 802.3)",
     "source_type": "行业标准", "url": "https://www.ieee802.org/3/",
     "description": "IEEE 以太网标准工作组官网", "reason": "清单验证通过，官方入口"},
    {"name": "某某机构", "node": "某节点", "verified": false, "note": "疑似无效机构"}
  ],
  "journal": [
    {"phase": "验证搜索", "node": "以太网标准(IEEE 802.3)", "query": "IEEE 802.3 Ethernet Working Group official", "results": 10, "extracted": 3}
  ],
  "sources": []
}
```

字段约束：

- **knowledge**：node 必须在 nodes 中；verified=true 的项必须带齐 `category_path/source_type/url/description/reason`（category_path 用 `-` 连接完整层级路径，末段与 node 一致）；verified=false 的项带 `note`（"疑似无效机构"或"已尽力"）。脚本自动把 verified 项并入 sources，**LLM 不要在 sources 里重复写清单条目**
- **sources**：仅增量发现条目，每条含 `name/category_path/source_type/url/description/reason`
- **journal**：记录本次的每一次搜索——`phase`（验证搜索/增量发现/扩量轮）、`node`、`query`（照抄实际查询词）、`results`（返回链接数）、`extracted`（提取候选数）
- 通用约束：name 和 url 不可为空；仅收录公开可访问的数据源；同一数据源只出现在一条分类路径下；分类路径术语统一；确保体裁多样性（数据集只是其中一类，不应占主导）

### 5. 后处理（调用脚本，全部确定性环节）

执行：

```bash
python .claude/skills/autosource/postprocess.py outputs/raw.json
```

脚本一次性完成以下全部环节，LLM 不得手工代做：

- 生成 `outputs/{领域词}_{时间戳}/` 目录（时间戳取自脚本系统时钟；同秒冲突自动加 `_1` 后缀）
- 证据校验：候选 URL 逐字比对证据留痕，不在即拒绝并计数
- **清单验证率计算**（自洽性指标）+ **verified 清单项自动并入 sources**
- **搜索日志**：journal 的查询词逐字比对证据留痕（不在标注"证据缺失"），生成 `{领域词}_{时间戳}_搜索日志.csv`
- 域名 + 名称联合去重（镜像站保留）；缺 name/url 的坏记录跳过并计数
- 导出 `{领域词}_{时间戳}_数据源清单.csv`（UTF-8 BOM、csv 标准库转义、固定表头：数据源名称, 分类路径, 数据源类型, 访问地址, 简要说明）
- 计算各节点候选数与体裁分布，写 `{领域词}_{时间戳}_stats.csv`（含空节点检测、"清单验证"列）
- 删除 `outputs/raw.json` 与证据留痕
- 打印统计汇总到 stdout（含清单核对与未验证清单）

### 6. 汇总报告

把脚本 stdout 的统计输出与分类树一起展示给用户：

```
领域: {领域描述}
分类树: {拆解结果}
{脚本 stdout 的统计部分（含候选/去重/证据校验/各节点分布）}
清单核对: 验证通过 X/Y 项
未验证清单（人工交接单）: {列表或"无"}
输出: {脚本 stdout 中的输出目录}/...
```

## 效果数据

`{领域词}_{时间戳}_stats.csv` 由脚本自动生成（每行一个分类节点）：

| 列 | 说明 |
|----|------|
| 领域 | 领域词 |
| 时间戳 | 运行时间 `YYYY-MM-DD HH:MM:SS`（脚本时钟） |
| 分类节点 | 叶子节点名 |
| 候选数 | 该节点去重后候选数 |
| 体裁分布 | 各体裁数量，按数量降序，格式 `官方文档:3; 数据集:5` |
| 无结果节点 | 无候选的节点名（用、连接，无则留空） |
| 总候选数 | 有效候选总数（去重前） |
| 去重移除 | 去重移除数 |
| 证据校验移除 | 证据校验拒绝数（URL 不在证据留痕中） |
| 清单验证 | 领域级自洽性指标：知识清单验证通过 X/Y（**不衡量对真实世界的完整性**） |
| 最终收录 | 去重后收录数 |
| 模型 | raw.json 中填写的模型名 |
| 脚本处理耗时(秒) | postprocess.py 自身处理耗时（不含搜索阶段） |

`{领域词}_{时间戳}_搜索日志.csv` 由脚本从 journal 生成（每行一次搜索：阶段/节点/查询词/返回链接数/提取候选数/证据缺失标注），供复盘"搜了什么、搜到了多少"。
