# AutoSource — 数据源自动发现

当用户输入 `/autosource <领域描述>` 时，执行以下流程。每次运行产出一个独立子目录 `outputs/{领域词}_{时间戳}/`。

- **领域词**：从用户输入的领域描述中提炼，取核心关键词（2-6 字），空格替换为 `_`。
- **时间戳**：当前时刻，格式 `YYYY-MM-DD-HHmmss`。

示例：输入 `帮我收集用于AI训练的GPU算力服务器相关数据源` → 目录 `outputs/算力服务器_2026-08-12-143000/`。

## 参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `<领域描述>` | 是 | 粗粒度文本，如 `算力服务器` |
| `-c` | 否 | 预设分类路径，如 `-c "GPU服务器" "CPU服务器"` |
| `-t` | 否 | 限定数据源类型，如 `-t "数据集" "产品文档"` |

## 执行流程

### 1. 领域拆解（用户未指定 -c 时执行）

将领域拆解为树状分类结构。遵循以下原则：

- 层级清晰：上下级严格包含，同级互斥不重叠
- 符合领域常识：分类体系与该领域公认知识体系一致
- 符合业务逻辑：粒度匹配实际使用场景，不过细也不过粗
- 深度自适应：不同领域层级数可不同（如金融可能 4 层，开源框架可能 2 层）
- 覆盖完整：覆盖该领域主要方向，无明显遗漏

将拆解结果以树形文字展示给用户。

### 2. 数据源搜索

调用搜索层 `/autosource-search`，传入领域词和叶子节点列表。搜索层负责：

- 对每个叶子节点执行至少 2 次 web_search（中英文各一次）
- 搜索词以"数据源可能的组织形式"为核心——数据库、排名、列表、标准、数据集、仓库等
- **禁止搜具体产品名或厂商名**（如 H100、NVIDIA）——这会把结果锚定到单一产品页
- 从每次搜索结果中提取**所有**符合条件的数据源（公共可访问、有 URL），不作数量筛选
- 第一轮结束后覆盖评估，薄弱节点自动扩量

等待搜索层返回全部候选数据源后进行下一步。

### 3. 结果整理

将搜索层返回的全部候选数据源整理为结构化 JSON（内部中间文件）。**提取阶段不做数量筛选**——所有搜索层返回的结果，只要符合下方约束，全部收录。去重和筛选在 Step 4 后处理环节完成。

```json
{
  "name": "数据源官方标准名称",
  "category_path": "以 - 分隔的层级分类路径",
  "source_type": "内容体裁（如：技术博客、产品文档、专业书籍、专利论文、开源仓库、数据集、排行榜/基准、行业标准、资讯平台等）",
  "url": "数据源主入口 URL",
  "description": "1-2 句话说明内容与核心价值"
}
```

约束：
- name 和 url 不可为空
- 同一数据源只出现在一条分类路径下
- 分类路径术语统一，同一概念不出现多种表述
- 仅收录公开可访问的数据源，不含需账号、付费、非公开的
- 确保体裁多样性——不能全部产出为同一类型（如全部是"产品文档"）。每个节点应有不同类型的数据源，覆盖产品文档、技术博客、开源仓库、数据集、排行榜/基准等多种体裁

将 JSON 写入 `outputs/{领域词}_{时间戳}/raw.json`。

### 4. 后处理

执行去重和 URL 校验脚本。若 `requests` 未安装，先执行 `pip install requests` 再运行脚本：

```bash
python -c "import requests" 2>/dev/null || pip install requests -q
python .claude/skills/autosource/postprocess.py outputs/{领域词}_{时间戳}/raw.json outputs/{领域词}_{时间戳}/clean.json
```

脚本完成：
- 域名 + 数据源名称联合去重（镜像站保留）
- HTTP HEAD/GET 校验 URL 可达性（超时 5s，重试 1 次）
- 输出清洗后的 JSON，并打印统计信息

将脚本的统计输出展示给用户。

### 5. 导出 CSV

读取 `outputs/{领域词}_{时间戳}/clean.json`，生成 CSV 文件 `outputs/{领域词}_{时间戳}/数据源清单.csv`。

- 编码：写入时在文件开头插入 UTF-8 BOM 字符（`﻿`），确保 Excel 直接打开不乱码
- 表头：数据源名称, 分类路径, 数据源类型, 访问地址, 简要说明

生成 CSV 后，删除中间 JSON 文件（`raw.json` 和 `clean.json`），只保留 CSV。

### 6. 汇总报告

向用户展示汇总：

```
领域: {领域描述}
分类树: {拆解结果}
共发现: X 条
有效 URL: Y 条 (Z%)
无效/移除: N 条
无结果节点: {列表或"无"}
输出: outputs/{领域词}_{时间戳}/数据源清单.csv
```

## 效果数据

每次执行完成后，写入 `outputs/{领域词}_{时间戳}/stats.json`，记录：

```json
{
  "domain": "领域描述",
  "timestamp": "ISO 8601",
  "total_found": 数量,
  "valid_urls": 数量,
  "valid_ratio": 比例,
  "empty_nodes": ["无结果的节点列表"],
  "model": "当前使用的模型"
}
```

用于后续提示词优化和效果对比。
