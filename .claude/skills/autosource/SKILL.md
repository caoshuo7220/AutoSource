# AutoSource — 数据源自动发现

当用户输入 `/autosource <领域描述>` 时，执行以下流程。

**分工原则**：LLM 只负责语义环节（领域拆解、搜索、相关性判断），一切确定性环节（时间戳、目录命名、证据校验、去重、CSV 编码、stats 统计、文件清理）由脚本保证。LLM 唯一需要产出的中间产物是 `raw.json`——写完它之后调用脚本即可，**不得手工代做脚本的活**。

**证据链**：每次 WebSearch/WebFetch 的原始结果由系统 hook 自动记录到 `outputs/search_log.jsonl`（PostToolUse hook，模型不可篡改）。脚本会校验 raw.json 里每个 URL 必须能逐字在证据留痕中找到，否则拒绝该条。**因此所有候选 URL 必须逐字照抄搜索结果，凭先验知识补的 URL 必须先补一次搜索、出现在结果里才能收录**。

- **领域词**：从用户输入的领域描述中提炼，取核心关键词（2-6 字），空格替换为 `_`，写入 raw.json 的 domain 字段。
- **输出目录**：脚本用自身系统时钟生成 `outputs/{领域词}_{时间戳}/`，LLM 不参与目录命名。

示例：输入 `帮我收集用于AI训练的GPU算力服务器相关数据源` → 目录 `outputs/算力服务器_2026-08-12-143000/`。

## 参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `<领域描述>` | 是 | 粗粒度文本，如 `算力服务器` |
| `-c` | 否 | 预设分类路径，如 `-c "GPU服务器" "CPU服务器"` |
| `-t` | 否 | 限定数据源类型，如 `-t "数据集" "产品文档"` |

## 执行流程

### 1. 领域拆解（用户未指定 -c 时执行）

将领域拆解为树状分类结构。遵循以下原则：

- 层级清晰：上下级严格包含，同级互斥不重叠
- 符合领域常识：分类体系与该领域公认知识体系一致
- 符合业务逻辑：粒度匹配实际使用场景，不过细也不过粗
- 深度自适应：不同领域层级数可不同（如金融可能 4 层，开源框架可能 2 层）
- 覆盖完整：覆盖该领域主要方向，无明显遗漏

**完整性自检**：初步拆解后，再自问一遍——"这个领域公认的主要子方向，有没有被遗漏的？"显式列出可能被漏掉的方向（某个细分技术、某类应用场景、某个层级），对照领域常识决定是否补入，再定稿。

将拆解结果以树形文字展示给用户。

### 2. 数据源搜索

调用搜索层 `/autosource-search`，传入领域词和叶子节点列表。搜索层负责：

- 对每个叶子节点从**两个维度**搜索（中英文）：组织形式（数据库/排名/列表/合集）+ 体裁入口（官方文档/手册/知识库/API 文档/论文）
- 对搜到的**集合页**（榜单/awesome-list/导航/文档站）用 WebFetch **展开**，提取其中列出的多个源——这是提升覆盖的关键
- 厂商/产品名**按意图区分**：禁止搜单个产品的规格参数页，但允许搜厂商/产品的文档站、知识库、API、帮助中心入口
- 从搜索与展开结果中提取**所有**符合条件的数据源（公共可访问、有 URL），不作数量筛选
- 第一轮结束后覆盖评估，薄弱节点自动扩量

等待搜索层返回全部候选数据源后进行下一步（per-node 统计由脚本在 Step 4 计算，无需搜索层返回）。

### 3. 结果整理 → 写 raw.json

将搜索层返回的全部候选数据源整理为结构化 JSON。**提取阶段不做数量筛选**——所有搜索层返回的结果，只要符合下方约束，全部收录。去重与筛选由脚本在 Step 4 完成。

写入 `outputs/raw.json`（固定路径，脚本处理完成后自动删除）：

```json
{
  "domain": "算力服务器",
  "nodes": ["AI训练GPU", "AI推理GPU", "图形渲染GPU", "通用计算", "ARM/国产处理器服务器", "高性能计算(HPC)", "服务器基准评测", "AI加速卡(GPU/NPU)", "服务器CPU"],
  "model": "当前使用的模型名（供 stats 溯源，不确定则留空字符串）",
  "sources": [
    {
      "name": "数据源官方标准名称",
      "category_path": "算力服务器-GPU服务器-AI训练GPU",
      "source_type": "官方文档",
      "url": "数据源主入口 URL",
      "description": "1-2 句话说明内容与核心价值"
    }
  ]
}
```

- **domain**：领域词（提炼规则见开头）
- **nodes**：全部叶子节点（传给搜索层的那组），用于空节点检测与 per-node 统计，缺了脚本会报错
- **category_path**：用 `-` 连接完整层级路径，末段必须与 nodes 中的某个叶子节点名一致
- **url**：必须逐字照抄搜索结果里的 URL（脚本做证据校验，不在证据留痕中的会被拒绝）
- **source_type**：内容体裁（技术博客、产品文档、专业书籍、专利论文、开源仓库、数据集、排行榜/基准、行业标准、资讯平台等）

约束：

- name 和 url 不可为空
- 同一数据源只出现在一条分类路径下
- 分类路径术语统一，同一概念不出现多种表述
- 仅收录公开可访问的数据源，不含需账号、付费、非公开的
- 确保体裁多样性——不能扎堆于某一体裁。每个节点应尽量覆盖多种体裁：官方文档、技术手册、知识库、API 文档、帮助中心、论文、数据集、开源仓库、排行榜/基准、行业标准、技术博客等。数据集只是其中一类，不应占主导

### 4. 后处理（调用脚本，全部确定性环节）

执行：

```bash
python .claude/skills/autosource/postprocess.py outputs/raw.json
```

脚本一次性完成以下全部环节，LLM 不得手工代做：

- 生成 `outputs/{领域词}_{时间戳}/` 目录（时间戳取自脚本系统时钟；同秒冲突自动加 `_1` 后缀）
- **证据校验**：每个候选 URL 必须逐字出现在证据留痕中（系统 hook 记录），否则拒绝该条并计数
- 域名 + 名称联合去重（镜像站保留）；缺 name/url 的坏记录跳过并计数，不中断整批
- 导出 `{领域词}_{时间戳}_数据源清单.csv`（UTF-8 BOM、csv 标准库转义、固定表头：数据源名称, 分类路径, 数据源类型, 访问地址, 简要说明）
- 计算各节点候选数与体裁分布，写 `{领域词}_{时间戳}_stats.csv`（含空节点检测）
- 删除 `outputs/raw.json` 与证据留痕
- 打印统计汇总到 stdout

### 5. 汇总报告

把脚本 stdout 的统计输出与分类树一起展示给用户：

```
领域: {领域描述}
分类树: {拆解结果}
{脚本 stdout 的统计部分}
输出: {脚本 stdout 中的输出目录}/{领域词}_{时间戳}_数据源清单.csv
```

## 效果数据

`{领域词}_{时间戳}_stats.csv` 由脚本自动生成（无需 LLM 手写），用于多次运行横向对比。格式为每行一个分类节点：

| 列 | 说明 |
|----|------|
| 领域 | 领域词 |
| 时间戳 | 运行时间 `YYYY-MM-DD HH:MM:SS`（脚本时钟） |
| 分类节点 | 叶子节点名 |
| 候选数 | 该节点去重后候选数 |
| 体裁分布 | 各体裁数量，按数量降序，格式 `官方文档:3; 数据集:5` |
| 无结果节点 | 无候选的节点名（用、连接，无则留空） |
| 总候选数 | 有效候选总数（去重前） |
| 去重移除 | 去重移除数 |
| 证据校验移除 | 证据校验拒绝数（URL 不在证据留痕中，即疑似编造） |
| 最终收录 | 去重后收录数 |
| 模型 | raw.json 中填写的模型名 |
| 脚本处理耗时(秒) | postprocess.py 自身处理耗时（不含搜索阶段） |
