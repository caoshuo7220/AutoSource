# AutoSource — 数据源自动发现

当用户输入 `/autosource <领域描述>` 时，执行以下流程。

**分工原则**：LLM 只负责语义环节（领域拆解、知识清单、搜索、验证与提取判断），一切确定性环节（时间戳、目录命名、证据校验、清单并入、去重、CSV 编码、stats 统计、搜索日志、文件清理）由脚本保证。**编排层不写任何文件**——raw.json 由搜索层按契约直接写入、后处理由搜索层收尾运行，编排层不转录、不手工代做脚本的活、不自创脚本。

**运行期边界**：本流程不写代码、不跑测试——运行中禁止调用 `karpathy-guidelines` 等开发类技能；唯一合法的 Bash 是 postprocess 命令（由搜索层收尾执行）。

**证据链**：每次 WebSearch 的原始结果由系统 hook 自动记录（PostToolUse，harness 侧），脚本校验每个候选 URL 与每个查询词必须逐字出现在留痕中——照抄纪律与校验细节见搜索层（编排层不产出 URL 候选）。

- **领域词**：从用户输入的领域描述中提炼，取核心关键词（2-6 字），空格替换为 `_`，作为 raw.json 的 domain 字段传给搜索层。
- **输出目录**：脚本用自身系统时钟生成 `outputs/{领域词}_{时间戳}/`。

示例：输入 `帮我收集用于AI训练的GPU算力服务器相关数据源` → 目录 `outputs/算力服务器_2026-08-12-143000/`。

## 参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `<领域描述>` | 是 | 粗粒度文本，如 `算力服务器` |
| `-c` | 否 | 预设分类路径，如 `-c "GPU服务器" "CPU服务器"` |
| `-t` | 否 | 限定数据源类型，如 `-t "数据集" "产品文档"` |

## 执行流程

### 1. 领域拆解（用户未指定 -c 时执行）

将领域拆解为树状分类结构。遵循以下原则：

- 层级清晰：上下级严格包含，同级互斥不重叠
- 符合领域常识：分类体系与该领域公认知识体系一致
- 符合业务逻辑：粒度匹配实际使用场景，不过细也不过粗
- 深度自适应：不同领域层级数可不同
- 覆盖完整：覆盖该领域主要方向，无明显遗漏

**完整性自检**：初步拆解后，再自问一遍——"这个领域公认的主要子方向，有没有被遗漏的？"显式列出可能被漏掉的方向（某个细分技术、某类应用场景、某个层级），对照领域常识决定是否补入，再定稿。

将拆解结果以树形文字展示给用户。

### 2. 知识清单（拆解完成后，零搜索）

基于领域知识直接列出该领域公认的**权威源清单**，不花一次搜索：

- 结构：`{名称, 所属叶子节点, 预期体裁}`，**URL 留空待验证**
- 规模：**尽量列全，不设条数上限**（产量优先；领域级权威源归到最相关节点名下）——列多列杂的代价只是多几次验证搜索，验证不通过的条目由"已尽力"处置自然过滤
- 粒度：**合集级与单篇级都可列**——合集级列机构/知识体系（垂直门户按合集级）；公认的权威单篇载体（行业白皮书、关键标准文件、重磅报告等）也可列，声明 `granularity`（默认合集级）
- **准入判据**：条目的 URL 必须定位到该领域的内容（有主题边界）。知网、专利库、百科、标准平台等跨领域通用平台首页不得列为清单项；平台的领域专属入口（该领域的分类检索页等）可列
- **清单自检**：列完后按机构类型维度自问一轮——标准组织 / 行业协会 / 厂商文档体系 / 学术文献库 / 评测机构 / 开源生态 / 百科知识库 / 公共数据平台，以及中文生态的对应物，各类都列了吗？有遗漏再补
- 预期体裁仅用于构造验证搜索词；最终 `source_type` 以验证时的实际形态为准，允许修正

将清单与分类树一起展示给用户。

### 3. 数据源搜索与收尾

调用搜索层 `/autosource-search`，传入**领域词 + 叶子节点 + 权威源清单 + 模型名**（模型名填当前实际使用的模型名）。搜索层负责全部后续环节：验证搜索 → 增量发现（每节点 6 次）→ 覆盖评估与扩量 → 按契约写入 `outputs/raw.json` → **收尾**运行后处理脚本并输出最终汇总（清单核对/未验证清单/输出目录）。

编排层零动作：不写文件、不转录、不手工核对证据。

**失败处置**：搜索层返回 `failed: true` 时**中止流程**——不调用后处理，如实向用户报告"搜索工具异常，本次运行中止"。
