# AutoSource — 数据源自动发现

**目标是发现该领域机构发布的成体系信息载体与非新闻单篇技术内容**——既包括"整理好的资源集合"（列表 / 数据库 / 合集 / 排名 / 标准文件），也包括"权威的内容入口"（官方文档站、技术手册、知识库、API 文档、帮助中心、论文库等），还包括非新闻的领域单篇技术内容（论文、专利、白皮书、标准文件、厂商技术文档、市场研究报告、测试评测报告的单篇等）。新闻、资讯与媒体文章不属于收录对象。

输入 `/autosource <领域描述>`，执行一条线性流程：

```
初始化（预留运行目录） → 0 领域拆解 → 1 厂商清单与官网搜索 → 2 知识清单 → 3 验证搜索 → 4 增量发现 → 5 覆盖评估与扩量 → 6 清单了结自检 → 7 收尾
```

流程中间没有交接停靠点——运行到最后一步（阶段 7 收尾）才算结束，任何一个中间环节都不是终点。**上下文增长是常态**：数据已分批落库，发生会话压缩时可凭 store 与 `coverage()` 恢复进度；不得以上下文长为由停靠、缩减配额或谎报进度。

## 分工与边界

**分工原则**：LLM 只负责语义环节（领域拆解、知识清单、搜索、验证与提取判断），一切确定性环节（时间戳、目录命名、入库校验、证据链、对账、去重、CSV 编码、stats 统计、搜索日志、折叠收尾、文件清理）由脚本保证。**数据落盘不靠写大文件**：新增条目、搜索日志与清单核对结果通过 record_sources / record_search / record_knowledge 工具入库（store.jsonl 由脚本持有、模型不可见），收尾由 finalize 工具一次性折叠；元数据（领域/节点/模型/厂商清单/知识清单声明）在 manifest.json，由模型 Write 一次（阶段 0-2）——清单核对结果**不进 manifest 转写**，随验证过程分批落库。

**运行期边界**：本流程不写代码、不跑测试——运行中禁止调用开发类技能；唯一合法的 Bash 是 postprocess 命令（初始化 `--prepare` 与阶段 7 报告命名 `--rename-report`）；数据写入只走五个 MCP 工具（record_sources / record_search / record_knowledge / coverage / finalize），禁止自创脚本或 Write 数据文件组装。

**存储机制自检**：五个 MCP 工具每次调用前由服务自检装配层（项目根锚定、hook 依赖的会话 ID 环境变量、运行目录证据文件）——装配层故障时工具报「存储机制自检失败」并按失败路径中止，按报错修装配层后重跑即可。

## 参数与运行约定

| 参数 | 必填 | 说明 |
|------|------|------|
| `<领域描述>` | 是 | 粗粒度文本，如 `算力服务器` |

- **领域词**：从领域描述中提炼核心关键词，空格替换为 `_`，作为 manifest.json 的 domain 字段。
- **输出目录**：流程开始时脚本预留 `outputs/run_{时间戳}/`（每次运行唯一），finalize 时重命名为 `outputs/{领域词}_{时间戳}/` 并生成交付物——最终产物位置以 finalize 返回的"输出目录"为准。

示例：输入 `帮我收集用于AI训练的GPU算力服务器相关数据源` → 目录 `outputs/算力服务器_2026-08-12-143000/`。

## 通用纪律

### 证据链与写入纪律（脚本强制校验）

- 候选 URL 必须**逐字照抄**搜索结果——每次搜索的原始结果由系统自动留痕（PostToolUse hook），record_sources 入库时逐条校验每个 URL 必须能逐字在留痕中找到，找不到的当场拒绝并返回原因（可立即修正重传）
- 每次搜索返回**两部分**：结构化结果链接（每条 `{title, url}`）与一段摘要正文。**两部分都是搜索返回的结果，同样重要，都要过目**——只读链接列表会漏掉摘要里出现的 URL；两部分都是合法证据来源，摘要正文里的 URL 与链接列表里的一样要提取。
- 禁止凭先验知识补 URL；模型"记得"某个权威源时，必须先专门搜一次、让它的 URL 出现在结果里，才能收录
- 禁止对 URL 做任何"规范化"（补路径、换域名、去参数）——照抄原文
- 禁止截短 URL（取父路径/裸域名）——校验为边界匹配，截短不放行
- URL 尾部的 `#…` 片段（数字引用锚点或文字锚点）不改变资源主体，**照抄即可**——脚本在输出 CSV 前确定性剥离纯数字引用锚点；漏抄片段不再被证据校验拒绝，但截短路径主体（父路径/裸域名）或去掉 query 参数（`?…`）仍会被拒绝
- record_search 的 query 照抄**实际发出的**查询词（脚本逐字比对留痕，不一致会被标注"证据缺失"）；**增量/扩量搜索提取为 0 时该条必填 `zero_reason` 拒收理由**（已收/垃圾域/无主题边界等）——收尾校验缺失即拒绝；补录 = 重传同 phase+node+query 行（末次覆盖）
- **数据落盘只走 MCP 工具**：record_sources（新增条目批次）、record_search（搜索日志批次）、record_knowledge（清单核对批次）、finalize（收尾折叠）——禁止自创脚本 / Write 数据文件组装（执行任何 Bash 如 `python build_xxx.py` 都会越界被权限白名单拦截弹窗）
- 只传契约字段，内部字段（如 `expected_type`）不写入
- **`category_path` 写法**：填所属**节点名本身**（如 `工业以太网交换机`）；领域有多层节点时用 `-` 连接完整层级（如 `算力服务器-GPU服务器-AI训练GPU`）。**不带条目名、不用 `/` 分隔**——写错该条归不到任何节点，入库即验当场拒绝并提示
- **`record_knowledge` 的 `name` 逐字照抄 manifest 里的名称**——收尾折叠按名精确对账，同义改写会被判成"漏录"、拒绝收尾
- **禁止手工核对证据**——不得用 grep/shell 循环/自创脚本等复合命令核对或重建（这是脚本的职责）；调查/排查用 Read 工具
- 被拒条目不进清单——入库校验由脚本执行，被拒明细在 record_sources 的返回里当场可见，修正后重传该条即可

### 提取规则

**收录判据（封闭集合）**：符合以下三条的候选必须收录——① 与领域相关（主题边界 = 机构发布的信息载体，定义见通用纪律"平台准入"）；② 公开可访问；③ 非重复（不与其他候选或已收录内容构成重复或替代关系，具体判定见下）。**判据之外没有其他判据**：体裁、粒度、页面类型均不影响是否收录——论文、专利、白皮书、标准文件、厂商技术文档的单篇同样收录，合集级与单篇级同样收录；新闻、资讯、媒体文章、个人内容一律不收录；单篇规格页或数据手册顺路命中时同样按判据处理，如实标为单篇级；同一机构的不同独立内容互不构成重复，无论是否同节点。**符合判据的一律收录**：不得以"清单会变杂""数量太多""同类已有"为由拒收；去重与清单质量由脚本负责——新闻、个人内容、垃圾域本就不属于收录对象，不是"怕清单变杂"的问题。

**平台准入（判据①的定义）**：收"机构发布的信息载体"——**成体系载体与单篇技术文件同等收录**：论文、专利、白皮书、标准文件、厂商技术文档的单篇一律收，不得以"不是成体系入口""只有单篇没有入口"为由拒收。

- **机构** = 领域相关的厂商、标准组织、行业协会、研究机构、评测机构、开源项目官方渠道（官方社区知识库、开源邮件列表与缺陷追踪属机构渠道）；媒体平台、通用平台、个人、经销商不属于——新闻门户与资讯媒体一律不收
- **信息载体** = 文档、手册、知识库、标准、论文、专利、数据集、报告、白皮书、代码仓库等成体系内容或单篇技术文件；新闻、资讯、宣传稿、导购、评测晒单不属于

跨领域通用平台的首页/根域名无主题边界，不收——**主题边界看机构、不看页面**（知网首页与交换机无关，领域内厂商的官网不受此限）。**厂商官网首页 / 根域名（含语言首页）可收，且每个厂商必收一条**——厂商 = 做本领域产品与方案的公司与品牌（标准组织、评测机构、大学不适用本条）；确实找不到官网时如实记"未找到官网"（进未验证清单，不阻断收尾）。平台的领域专属入口（专利库的该领域分类检索页、标准平台的该领域检索页）可收；自身不提供领域内容、仅链接至其他页面的纯导流页不收；百科词条、问答、个人博客与论坛帖不收。垃圾域与低价值聚合平台（淘宝/知乎/CSDN 等大平台）由脚本名单（store.GARBAGE_DOMAINS）在入库时直接拒绝、收尾时过滤。通用平台对领域有价值的信息写入该领域条目的 `description` 传递（如"全国标准平台可检索"）。

**重复与替代关系（判据③的定义）**：

- **语义重复与替代（只收其一）**：同一 URL 内容重复出现；同一主题的合集入口与其包含的同一具体内容页同时出现时，优先收合集入口、不收该单篇；同一内容的多个语言版本按 **中文 > 英文 > 其他语言** 只收一个（判定依据：URL 语言特征 `/zh-cn`、`/zh/`、`cn` 子域、标题与内容语言；无中文版本则收英文版，仅有一个版本时照收，站点中文版内容不全时按实际存在的版本收）；同一内容的镜像或转载页只收其一，可识别原始页时优先原始页。
- **不构成重复**：同一机构、同一域名、同一产品线、同一体裁、同一节点内的不同独立内容均不构成重复（如同一厂商的官网首页与其文档门户是两个独立条目，互不替代）。
- **脚本去重机制**：record_sources 入库阶段 URL 原文完全相同（不截短、不去参数）的重复由脚本幂等跳过；收尾阶段脚本按"域名 + 名称"联合去重，**URL 剥离引用锚点后相同的一律判重**——同一入口被 record_sources 与 record_knowledge 各记一次、两次名称措辞不同时只留一条；同一域名的不同独立内容须使用不同名称收录（名称应如实使用资源名称，不得仅为规避去重而改名），同名同域会被去重移除；record_knowledge 同名重录为状态更新，收尾取末次。
- **重复无法确定时按不重复处理并收录**；内容级重复仅在可判断时按上述规则处理（脚本只保障 URL 原文级的幂等，不做内容级去重）。

**判断方式**：每次搜索返回的 N 条结果逐条过目、逐条判断——禁止因"整体印象"（如"都是同一来源的内容""都是转载页"）而对该批检索结果一次性放弃；提取为 0 的唯一前提是逐条判断后确实没有一条符合判据，禁止"没看到合集入口就放弃该批结果"。零提取时须在搜索日志 `zero_reason` 中写明拒收理由（已收/垃圾域/新闻资讯/个人内容/无主题边界等）——收尾脚本校验缺失或与结果域名证据矛盾时拒绝收尾。**"非成体系载体""只有单篇没有入口"不构成拒收理由**——论文、专利等单篇技术文件本就是收录对象，零提取只能出自"结果整体与领域无关 / 命中垃圾域 / 已收录"三类情形。

**标注**：每条候选声明 `granularity`（合集级/单篇级，如实标注，脚本不拦截），单篇级在 `reason` 写明依据（如"单篇行业报告"）；`source_type` 是内容形态标签（如"厂商文档""市场研究报告""开源项目"），不填机构名、领域名或网址。**标"官网"的只限站点入口**（根域名 / 语言首页）——厂商站内的产品页、文档页、介绍页等按实际形态标注（文档 / 报告 / 数据库…），不标"官网"。

**提取率自查（非准入条件）**：结果集与领域相关的查询，10 条结果中机构信息载体通常占 2-4 条——其余为新闻资讯、转载聚合、垃圾域或已收录内容；整批结果确为低相关或非目标内容（书商、元器件站、SEO 聚合页）时如实提取 0，不得为提高数量收录。此标尺只触发逐条复核，不构成判据、不能覆盖收录判据；命中易失效词形导致结果集整体低相关时，本标尺不适用；已收录内容随运行推进增多时，不符合比例上升属正常，节点级提取率复核见阶段 4。

### 失败路径（搜索工具异常）

搜索大范围失败（多数查询无有效结果返回）时：停止搜索，**不调用 finalize、不产出交付物**，**向用户显式声明失败状态**（以一句"本次运行失败"开头，随后简述原因），不伪造候选，如实报告"搜索工具异常，本次运行中止"。已预留的运行目录保持为空残留。

## 初始化 · 预留运行目录

流程开始时先执行（该 Bash 命令在权限白名单内，直接运行）：

```bash
python .claude/skills/autosource/scripts/postprocess.py --prepare
```

脚本创建 `outputs/run_{时间戳}/`（每次运行唯一，同秒自动加后缀）并打印完整路径——**照抄该路径**：阶段 2 用它写 manifest.json，阶段 7 传同一路径收尾。该目录自此归本次运行专属；若后续搜索失败中止，它保持为空残留。

## 阶段 0 · 领域拆解

将领域拆解为树状分类结构。

**禁止读取 outputs/ 下历史运行的产物**——历史清单是上轮结果的基线，照搬会继承上轮的遗漏与偏差；读取被权限拦截属护栏按设计工作，不是缺陷。

**拆解原则**：

- 层级清晰：上下级严格包含，同级互斥不重叠
- 符合领域常识：分类体系与该领域公认知识体系一致
- 符合业务逻辑：粒度匹配实际使用场景，不过细也不过粗
- 深度自适应：不同领域层级数可不同
- 覆盖完整：覆盖该领域主要方向，无明显遗漏
- 节点规模由覆盖完整性决定——不以搜索次数或运行时长为由合并节点（搜索成本由设计承担，不是拆解的约束）

### 节点搜索画像

完成分类树后，为每个叶子节点补充以下轻量信息：

- **节点边界**：说明该节点包含和不包含的内容，减少跑题和节点间重复
- **核心搜索词**：中文名、英文名、常见缩写或行业别名，以及该节点的行业术语与细分场景词（如"运营商级交换机"→ 承载网 / 城域网 / 集采）
- **相关来源类型**：该节点适合搜索的资料形态
- **相关来源角色**：可能发布该类资料的机构角色

搜索画像仅用于阶段 3/4 构造查询词和阶段 5 覆盖检查，不改变 `nodes` 字段契约，不要求将画像内容写入最终清单。具体机构仍由知识清单提供一部分，并通过搜索继续发现，禁止为填画像强行编造机构名称。

**完整性自检**：初步拆解后，再自问一遍——"这个领域公认的主要子方向，有没有被遗漏的？是否遗漏了相关配套生态？"显式列出可能被漏掉的方向（相关配套生态、某个细分技术、某类应用场景、某个层级），对照领域常识决定是否补入，再对照节点搜索画像逐节点复查，补上遗漏。

**输出**：将拆解结果以树形文字展示给用户。无需等待用户确认。

## 阶段 1 · 厂商清单与官网搜索

**清单内容**：凭领域知识列出本领域厂商（做本领域产品与方案的公司与品牌），按节点归属，尽量列全——每项 `{厂商名, 所属节点}`。

**查询词**：每个厂商只搜一次，固定 `{厂商名} 官网`，不加其他词、不做英文版。

**通过标准**：命中官网首页 / 根域名（含语言首页）即通过（`source_type` 标"官网"）；找不到记 `verified=false` + note="未找到官网"。

**记录时机**：核对结果用 record_knowledge 分批落库（每 ~10-15 项一批）；厂商清单写进 manifest 的 `vendors` 数组（阶段 2 写 manifest 时一并写入）。

## 阶段 2 · 知识清单（零搜索）

基于领域知识直接列出该领域的**知识清单**：

**列什么与列多少**：

- 结构：`{名称, 所属叶子节点, 预期体裁}`，**URL 留空待验证**
- 粒度：**合集级与单篇级都可列**——合集级列机构 / 知识体系（垂直门户按合集级）；公认的权威单篇载体（行业白皮书、关键标准文件、重磅报告等）也可列。实际粒度在验证时按形态确定（与 `source_type` 同规矩），**manifest 不声明 `granularity`**
- 规模：**尽量列全，不设条数上限**（产量优先；领域级权威源归到最相关节点名下）——验证不通过的条目按"未找到官方入口"自然过滤，**无需以搜索成本为由缩减清单**

**准入判据**：条目必须指向该领域的内容（有主题边界）；跨领域通用平台的收与不收见通用纪律"平台准入"。

**清单自检**：列完后按机构类型维度自问一轮——标准组织 / 行业协会 / 厂商文档体系 / 学术文献库 / 评测机构 / 开源生态 / 公共数据平台，以及中文生态的对应物，各类都列了吗？再对照节点搜索画像逐节点复查，补上遗漏。这里的检查用于指导后续搜索；清单没有覆盖的节点在阶段 4 主要依靠节点搜索画像构造查询，不要求为每个来源类型强行编造机构名称。

**预期体裁**：仅用于构造验证搜索词；最终 `source_type` 以验证时的实际形态为准，允许修正

**输出**：将清单展示给用户（无需等待用户确认）。随后立即 Write **manifest.json**（阶段 0-2 声明版）到初始化 `--prepare` 打印的运行目录——`{domain, nodes, model, vendors, knowledge}`：`vendors` 是阶段 1 的厂商清单（每项 `{name, node}`），`knowledge` 是本阶段的清单项（每项 `{name, node, 预期体裁}`），URL 留空待验证；**必须整体 Write，禁止 Edit**（outputs 目录权限只放行 Write）。这是唯一由模型直接 Write 的元数据文件，**整轮只写这一次**——清单核对结果不进 manifest，随验证过程用 record_knowledge 落库（见阶段 1/3/5）。

```json
{
  "domain": "交换机",
  "nodes": ["数据中心交换机", "以太网标准(IEEE 802.3)", "..."],
  "model": "会话提供的模型名（未提供时留空）",
  "vendors": [
    {"name": "Cisco", "node": "数据中心交换机"},
    {"name": "华为", "node": "数据中心交换机"}
  ],
  "knowledge": [
    {"name": "IEEE 802.3 以太网工作组", "node": "以太网标准(IEEE 802.3)", "预期体裁": "行业标准"},
    {"name": "Cisco Nexus 文档体系", "node": "数据中心交换机", "预期体裁": "官方文档"}
  ]
}
```

字段约束：`domain / nodes` 全轮不变；`model` 可选（会话未明确提供可靠模型名时留空，不编造）；vendors 项只含 name/node，knowledge 项只含 name/node/预期体裁（name 不可为空，URL 留空待验证）。通用约束：公开可访问与非重复见通用纪律"收录判据"；同一具体资源或同一来源体系在知识清单中只声明一次，同一机构的不同内容体系可分别声明于最相关节点；分类路径术语统一；通用平台规则见通用纪律"平台准入"。

## 阶段 3 · 验证搜索

阶段 0/2 的产出即本阶段输入：

```
领域词: 交换机
叶子节点:
  - 数据中心交换机
  - 企业园区交换机
  - ...
知识清单:
  - {名称: IEEE 802.3 以太网工作组, 节点: 以太网标准(IEEE 802.3), 预期体裁: 行业标准}
  - {名称: Cisco Nexus 文档体系, 节点: 数据中心交换机, 预期体裁: 官方文档}
  - ...
```

- **查询词构造**：按来源实际情况自由组合（每词 2-4 个组件），组件池——**来源识别（必带其一）**：原名 / 英文名 / 缩写 / 别名；**入口意图**：官方文档 / 官网 / 入口 / 目录 / 数据库 / 标准列表 / 仓库；**辅助**：领域词、地域词和语言词。组合示例：`中国电子技术标准化研究院 交换机 标准`、`IEEE 802.3 Ethernet Working Group official`、`SONiC open source networking documentation`、`CCSA 通信行业标准 检索`。若清单项所属叶子节点有节点搜索画像，可按需加入该节点的核心搜索词、相关来源类型或来源角色，但不要求每次查询全部加入。
- **首轮优先官方入口**：验证搜索的目标是官方入口 URL——首轮查询词优先用"来源识别 + 官网 / 官方文档"（如 `中国通信标准化协会 官网`、`ETSI official documentation`）；暂不使用"来源识别 + 具体体裁词"（如 `中国电子技术标准化研究院 白皮书`）——这类词易命中低相关结果。
- **每项固定搜 2 次，两次取不同角度**：两次查询词不得重复，在组件池内换来源识别或入口意图词，语言随之适配。两次结果里的候选全部按收录判据处理，不只取验证目标那一条。
- **落空处理**：两次都没搜到官方入口 → 标记未验证，留扩量轮换角度重试（阶段 5）
- **通过标准（按条目粒度对应）**：目标始终是该机构的官方入口 URL；搜不到入口时按以下标准降级处理，扩量轮换"官网/官方文档"角度兜底。
  - 合集级清单项：搜索结果中出现该机构的**入口 URL**（官网首页 / 根域名（含语言首页） / 文档门户 / 目录 / 列表页）即通过。**以下不算入口**：帮助页 / FAQ / 政策条款页 / 单篇 PDF / 新闻公告页 / 课程页 / 机构介绍页 / 带跟踪或翻译参数的 URL（`?utm_`、`?trk=`、`?_x_tr_sch=` 等）——落在这些形态上按"未通过"处理，换角度重试
  - 合集级清单项只搜到合集内**单篇载体**（PDF、单条 KB 等）：**不算通过**——按"未通过"落库（note="仅找到单篇载体"），扩量轮换角度专找入口（如 `{机构名} documentation`）；换角度仍找不到入口 → **定案时以该单篇通过**（granularity 单篇级），reason 注明"仅找到单篇载体，未找到合集入口"
  - 单篇级清单项：搜索结果中出现**该载体本身**即通过
  - 连单篇载体都没有 → 标记未验证，留待扩量轮换角度重试后按阶段 5 定案
- **通过后**：在**清单项内**填上 `category_path（完整路径）/ source_type / granularity / url / description / reason`（URL 照抄），预期体裁允许按实际形态修正——核对结果用 **record_knowledge 分批落库**（每 ~10-15 项一批，与 record_search 同节奏；verified=true 项 URL 入库即验证据链，被拒当场修正重传）
- **未通过**：**当场**用 record_knowledge 落库 `verified=false` + note——**note 按当次搜索结果如实取一个：`未找到官方入口` / `仅找到单篇载体` / `疑似无效机构`**；不急于分类，扩量轮换角度重试后按阶段 5 定案（改判时同名重录即状态更新）。**未通过项必须当场落库，不得攒到定案时再记**——会话中断时未落库的核对结果会整体丢失
- **搜索日志记录**：每 ~10-15 次验证搜索调用一次 record_search 批量入库——验证搜索项 `phase/node/query/results/extracted/verified`（**phase 只允许三个取值：验证搜索 / 增量发现 / 扩量轮**；**verified=该次验证是否通过**：搜到该机构入口填 true、未通过填 false；**extracted 只记顺路新源数，验证通过本身不计入**——两个字段各装一个事实；一次搜索验证了同机构多个入口时，verified=true 只记一次即可）；增量发现项的 verified 留空即可（脚本按 phase 过滤，填了也不计入验证账）。query 照抄实际发出的查询词——逐条记、批量入，不要每次搜索单独调用
- **阶段中途不与用户交互**：不产出状态汇报、不请用户选择方向（含"是否继续 / 是否缩小领域"）——本阶段做完即进入阶段 4

## 阶段 4 · 增量发现

**搜索次数**：每节点**固定 20 次**搜索（基底 16 次 + 扩充 4 次）：

- **固定 4 次**（组织形式类中文/英文各 1 次，体裁类中文/英文各 1 次）：各取与节点最相关的一个词
- **自由 8 次**（仅中文搜索词）：从角度池选 8 个**本节点尚未覆盖的角度**各搜一次，优先覆盖不同的来源类型和来源角色，避免在同类角度上重复换词
- **实体 4 次**（本节点搜索过程中新发现的实体）：从中选 4 个，按下方"实体选题"构造规则各搜一次入口；清单或厂商清单中已列出的机构不算新实体；新实体不足 4 个时，空缺次数退回角度池补角度
- **扩充 4 次**（角度池或实体选题均可）：基底 16 次完成后固定执行，不设续批判定、不做产出门槛，做完即进入阶段 5。**与阶段 5 扩量轮区分**：扩充是基底后的延续（每节点必经），扩量轮是阶段 5 对薄弱节点的定向补搜——两者不是一回事，扩充不得并入扩量轮执行。

**角度池**（包括但不限于）：

- 学术类：论文 / 专利 / 文献库
- 组织形式类：列表 / 排名 / 数据库 / 标准 / 仓库 / 合集
- 体裁类：官方文档 / 开发者文档 / 手册 / 知识库 / API 参考 / 帮助中心 / 白皮书 / 市场研究
- 数据类：数据集 / 开放数据
- 生态类：社区（含开源项目社区与邮件列表）
- 来源角色类：标准组织 / 监管机构 / 政府部门 / 行业协会 / 厂商 / 研究机构 / 大学 / 评测机构 / 基金会 / 公共数据平台

**易失效词形（两类已知易命中低相关结果集的模式）**：① **标准**角度词单独使用（缺领域词 + 入口词）会命中标准平台首页——必须组合"领域词 + 入口词"（检索 / 列表 / 分类 / 目录 / 合集）；**论文、专利角度不受此限**：它们的目标就是单篇技术文件的内容页（IEEE / arXiv / 知网 / 万方的论文页、Google Patents 的专利页），**命中即按单篇级收录**，只有平台首页与整体无关的批次才零提取；② 英文查询词以 `list / standard list / paper list / market report / directory` 等未组合泛化后缀结尾会命中书店页、股票新闻、手册镜像站——优先组合"领域词 + 厂商内容入口词"（documentation / official docs / datasheet / support / products），尽量避免 directory / registry / collection 这类泛化目录词。

- **查询词构造**（两类选题）：
  - **框架内角度**（角度池）：围绕当前节点名称或节点搜索画像中的核心搜索词，组合一个发现型角度词，优先使用该节点适用的来源类型或来源角色；查询词必须包含领域词（或节点核心词），角度词尽量带入口词；次数与语言分配见上方"搜索次数"；必须带发现型词汇；画像中的机构名称不是必须逐一搜索的清单——以上约束只管本类。
  - **实体选题**（新发现的实体）：对与本节点强相关的实体（机构 / 厂商 / 产品 / 规范等具体对象），用"实体名 + 入口词"作查询词（如 `超以太网联盟 UEC 规范`），**可不含领域词/节点核心词**；搜索目标是该实体的成体系载体入口，不单独搜规格参数页；命中结果的收录按通用纪律"收录判据"执行。清单或厂商清单中已列出的机构不在本类范围内，本类主要用于增量发现中新出现的机构。
- **提取纪律**：全量提取、URL 逐字照抄、每条带 reason、遵守收录判据与标注规则
- **记录时机（group commit）**：基底 16 次搜索完成后，把该节点新增条目用一次 record_sources 入库、16 条搜索记录用一次 record_search 入库；扩充 4 次完成后再各入一次（每节点合计 20 条搜索记录）——两个批量调用一组，不要每次搜索后逐条调用。批量大小 = 单节点批次量（约 15-25KB），远离截断边界；入库后该节点内容即由脚本持有，会话压缩也不丢失。**提取为 0 的搜索行必须带 `zero_reason` 拒收理由**；收尾校验每节点增量搜索 ≥20 次（不足拒绝并点名）——如实记录，不得谎报次数
- **入库前自查**：入库前先算本节点提取率（收录条数 ÷ 搜索次数）；明显低于 1 条/搜时，回头重审零提取搜索的结果（重审不重新搜索），确认漏收补调 record_sources 后再入库
- **阶段中途不与用户交互**：不产出状态汇报、不请用户选择方向（含"是否继续 / 是否缩小领域"）——本阶段做完即进入阶段 5

## 阶段 5 · 覆盖评估与扩量（含清单定案）

**薄弱判定**：每节点统计候选数与体裁分布，并按 6 个核心来源维度核对覆盖情况（官方组织与标准 / 厂商与产品生态 / 学术与研究 / 开源与社区 / 数据集与公共数据 / 行业协会与市场信息），按以下标准判定薄弱节点。候选数与提取数可从 **coverage()** 读取（只测条数缺失）；体裁/来源维度是否单一由模型按判定表在会话内判断：

| 情形 | 判定 |
|------|------|
| 候选少（0 条或明显少于同级节点）+ 清单项有未验证 | **薄弱**——扩量轮优先把未验证清单项验证掉，而非无目标的泛搜 |
| 候选少 + 清单项全验证通过 | **不薄弱**——权威源就这些，强行扩充只会引入长尾噪声 |
| 体裁单一 | **薄弱**（补搜换体裁词） |
| 来源维度单一（条目明显集中于一个维度，如全是厂商文档） | **薄弱**——扩量轮按空缺维度定向补搜（用来源角色词构造查询）；根据节点搜索画像判断相关来源角色是否适用，空缺维度对该节点明显不适用时不补 |

**未验证项定案**（扩量轮内，每轮换一个角度：中英切换 / 全称缩写别名 / `机构名+官网/官方文档`）：

- 换角度重试后仍搜不到该机构存在的**任何证据** → 疑似幻觉/过时 → **从有效来源中剔除**，note="疑似无效机构"
- 能搜到该机构存在、但始终找不到官方入口 → 换角度重试 ≤2 次仍失败 → **留在未验证清单**，note="未找到官方入口"
- 只找到合集内单篇载体（note="仅找到单篇载体"）→ 换角度专找入口 ≤2 次仍找不到 → **以该单篇通过**（granularity 单篇级），reason 注明"仅找到单篇载体，未找到合集入口"
- 定案结果（剔除/留未验证/换角度后转验证通过）用 **record_knowledge 落库**（verified=false 项带 note；换角度后验证通过的项按阶段 3 字段齐套重录——同名重录即状态更新）

**终止条件**：所有节点**非薄弱或已收敛** **且** 两栏清单项（vendors + knowledge）全部了结（验证通过或已定案）。**扩量轮按节点独立判断，不再全局共享轮数**：仍薄弱且未收敛的节点继续扩量，非薄弱节点停止；某节点在一轮扩量中无任何新增有效来源时，该节点视为收敛并停止，如实报告。

**扩量轮内的搜索范围**：① 未验证项（两栏）换角度验证（每轮每项 1 次；含 note="仅找到单篇载体"的合集级项——它们的目标是找入口）；② 体裁单一的节点换体裁词补搜（每轮 ≤4 次）；③ 来源维度单一的节点按空缺维度补搜（每轮 ≤4 次，用来源角色词构造查询）。除这三类外不做其他补搜。

**记录时机**：扩量轮每节点收敛后，把该节点补充条目与搜索记录按节点批量入库（同阶段 4 的两个批量调用）。**收尾前用 coverage() 自查**：missing 是粗略缺口信号（提取数含去重前与跨节点顺路发现、已收数是幂等去重后的入库数，两口径天然有差）——小额 missing 属正常，不触发补搜；只有当 missing 接近该节点一整批提取量时才怀疑漏调了 record_sources，补该节点。

- **阶段中途不与用户交互**：不产出状态汇报、不请用户选择方向（含"是否继续 / 是否缩小领域"）——本阶段做完即进入阶段 6

## 阶段 6 · 清单了结自检

**manifest 无需重写**——阶段 0-2 写入的声明版即终版；清单核对结果已随阶段 1/3/5 用 record_knowledge 分批落库。本阶段只做了结对账：

- **应录 vs 已录**：manifest 两栏（vendors + knowledge）共 N 项，各批 record_knowledge 返回的 accepted 数累计应等于 N。少于 N → 逐项排查漏录项并补录（verified=true 项齐套 `category_path/source_type/url/description/reason`；未验证项带 note）
- 被剔除的疑似无效机构**同样要录**（verified=false + note="疑似无效机构"），供报告展示
- 对账完成后**不要结束回合**——立即执行阶段 7 收尾。finalize 会独立复核：声明清单中无核对记录的项**拒绝收尾并点名**（漏录在此响亮失败，补录后重跑即可，运行目录不会被重命名）

## 阶段 7 · 收尾

**流程到此并未结束，没有交接环节——继续执行收尾，把流程跑完。** 立即调用 **finalize 工具**（`<运行目录>` 照抄初始化 `--prepare` 打印的路径）：

```
finalize(run_dir=<运行目录>)
```

折叠一次性完成 证据终检 / 清单并入 / 去重 / CSV / stats / 溯源 / 搜索日志 / 清理——运行目录重命名为 `outputs/{领域词}_{时间戳}/`，store 与 manifest 归档进 intermediate/（store_input.jsonl / manifest_input.json）——把 finalize 的返回文本**原样展示给用户作为最终汇总**（含清单核对、输出目录）。**防截断哨兵**：若增量/扩量搜索有提取、但来源 0 入库且清单无验证通过项，finalize 会拒绝并报错——说明漏调了 record_sources，补录后重跑即可（纯清单验证的运行不受影响；失败时运行目录不会被重命名）。**清单了结哨兵**：声明清单中无核对记录的项会拒绝收尾并点名——漏调 record_knowledge 同样响亮失败，补录后重跑即可。**收尾护栏**：① 每节点增量搜索不足 20 次拒绝并点名（配额缩水/谎报过不了收尾）；② 增量/扩量零提取缺 `zero_reason` 拒绝并点名；③ 理由与结果域名证据矛盾（声称已收但域名不在清单、声称垃圾域但域名非垃圾域）拒绝并点名——补搜补录/补理由后重跑即可。

**收尾的最后一步：写领域分析报告。** 先 Read `.claude/skills/autosource/references/分析报告模板.md`，按其模板把报告 Write 到 finalize 返回的"输出目录"里的 `分析报告.md`（**内容由模型写、文件名由脚本命名，不要自行命名**；**统计数字一律不写**——"数据总览"段由脚本在下一步自动生成）。写完报告，立即执行（该 Bash 命令在权限白名单内，直接运行；`<输出目录>` 照抄 finalize 返回的"输出目录"）：

```bash
python .claude/skills/autosource/scripts/postprocess.py --rename-report <输出目录>
```

脚本把报告重命名为 `{目录名}_分析报告.md`（与数据源清单/stats 同前缀，第三交付物）。之后运行到此结束，没有修正重跑环节。
