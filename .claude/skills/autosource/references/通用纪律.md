## 通用纪律

### 证据链与写入纪律（脚本强制校验）

- 候选 URL 必须**逐字照抄**搜索结果——每次搜索的原始结果由系统自动留痕（PostToolUse hook），record_sources 入库时逐条校验每个 URL 必须能逐字在留痕中找到，找不到的当场拒绝并返回原因（可立即修正重传）
- 每次搜索返回**两部分**：结构化结果链接（每条 `{title, url}`）与一段摘要正文。**两部分都是搜索返回的结果，同样重要，都要过目**——只读链接列表会漏掉摘要里出现的 URL；两部分都是合法证据来源，摘要正文里的 URL 与链接列表里的一样要提取。
- 禁止凭先验知识补 URL；模型"记得"某个权威源时，必须先专门搜一次、让它的 URL 出现在结果里，才能收录
- 禁止对 URL 做任何"规范化"（补路径、换域名、去参数）——照抄原文
- 禁止截短 URL（取父路径/裸域名）
- URL 尾部的 `#…` 片段（数字引用锚点或文字锚点）不改变资源主体，**照抄即可**——脚本在输出 CSV 前确定性剥离纯数字引用锚点
- record_search 的 query 照抄**实际发出的**查询词；**增量/扩量搜索提取为 0 时该条必填 `zero_reason` 拒收理由**（已收/垃圾域/无主题边界等；补录 = 重传同 phase+node+query 行，末次覆盖）
- **数据落盘只走 MCP 工具**：record_sources（新增条目批次）、record_search（搜索日志批次）、record_knowledge（清单核对批次）、finalize（收尾折叠）——禁止自创脚本 / Write 数据文件组装
- 只传契约字段，内部字段（如 `expected_type`）不写入
- **`category_path` 写法**：填所属**节点名本身**（如 `工业以太网交换机`）；领域有多层节点时用 `-` 连接完整层级（如 `算力服务器-GPU服务器-AI训练GPU`）。**不带条目名、不用 `/` 分隔**（写错归不到任何节点）
- **`record_knowledge` 的 `name` 逐字照抄 manifest 里的名称**——收尾折叠按名精确对账，同义改写会被判成"漏录"、拒绝收尾
- **禁止手工核对证据**——不得用 grep/shell 循环/自创脚本等复合命令核对或重建（这是脚本的职责）；调查/排查用 Read 工具
- 被拒条目不进清单——被拒明细在 record_sources 返回里可见，修正后重传即可

### 子代理派工（阶段 1/3/4/5）

**分工边界**：阶段 0（画像）与阶段 2（清单）由主流程做；阶段 1/3/4/5 的搜索、提取、落库**整体下放子代理**；阶段 6 定案与阶段 7 收尾回主流程。主流程只做三件事——**编排**（派工）、**验收**（处理失败组）、**对账**。**搜索一律不在主会话里发**；条目明细不回流主上下文。

**开工自检（每次运行、开搜之前只做一次）**：manifest 落盘后派一个只做自检的小代理，**按此顺序**：① ToolSearch 加载 store 工具（record_sources / record_search / record_knowledge / coverage）；② **发一次 WebSearch**（任意一次真实检索即可，如 `<某个厂商名> 官网`——**留痕文件由 hook 首次触发时才创建**，五个 MCP 工具在留痕不存在时一律报「证据留痕不存在」，跳过这步后面必然失败）；③ 调一次只读 `coverage(run_dir)`（返回各节点已收/提取计数即通）；④ 读一次 manifest.json。**四项全过才开搜；任一不通即中止本次运行**（先修装配层再重跑），不静默跳过、不带病开搜。

**派工词必含四项**：

1. **先加载工具**——ToolSearch `select:mcp__autosource-store__record_sources,mcp__autosource-store__record_search,mcp__autosource-store__record_knowledge`（延迟加载的工具，不加载就调不了）
2. **`run_dir` 的具体路径**——照抄进派工词，子代理原样传给 record_* 工具
3. **本组的节点名与本阶段名**，并写明"先 Read 通用纪律与本阶段对应文件，按文件里的细则执行"——搜索次数、查询词构造、提取纪律**不在派工词里复述**
4. **回执格式**（见下）

**回执格式**（只回一行，条目明细不进主上下文）：

    阶段{k}-组{n} · 搜索 {a} 次 / 入库 {b} 条 / 被拒 {c} 条

**被拒处理**：record_sources 返回 `rejected:[{index,name,url,reason}]`——**当场按 reason 修正后重传**（URL 照抄留痕里的写法、名称逐字照抄 manifest、`source_type` 按本文件「标注」段填）；同一批最多重传 2 次，仍被拒的放弃并计入回执的"被拒数"。

**分组粒度与 `phase` 字面量**（主模型只认节点名，不做算术）：

| 阶段 | 分组 | `phase` 填什么 |
|---|---|---|
| 1 厂商官网 | 每 1 节点一组 | `厂商官网` |
| 3 清单验证 | 每 1 节点一组 | `验证搜索` |
| 4 增量发现 | 每 1 节点一组 | `增量发现` |
| 5 扩量 | 每 1 节点一组 | `扩量轮` |

`phase` 按上表写死——收尾按前缀归组（验证 / 增量 / 扩量）做统计与配额护栏，写错（`1`、`阶段一`）这一行就归不进组、统计与护栏都看不见它。

**派工节奏**：按阶段分批——一个阶段的组一次派出（不等单个回执），**收齐本阶段全部回执后**才进下一阶段。失败或超时的组重派接班代理：**先调 `coverage()` 看该节点已完成量**，拿不准就整组重做——条目按 URL 幂等去重、日志按（阶段, 节点, 查询词）末次覆盖，重做不会写坏数据。

### 提取规则

**收录判据（封闭集合）**：符合以下三条的候选必须收录——① 与领域相关（主题边界 = 机构发布的信息载体，定义见通用纪律"平台准入"）；② 公开可访问；③ 非重复（不与其他候选或已收录内容构成重复或替代关系，具体判定见下）。**判据之外没有其他判据**：体裁、粒度、页面类型均不影响是否收录——论文、专利、白皮书、标准文件、厂商技术文档的单篇同样收录，合集级与单篇级同样收录；新闻、资讯、媒体文章、个人内容一律不收录；单篇规格页或数据手册顺路命中时同样按判据处理，如实标为单篇级；同一机构的不同独立内容互不构成重复，无论是否同节点。**符合判据的一律收录**：不得以"清单会变杂""数量太多""同类已有"为由拒收；去重与清单质量由脚本负责——新闻、个人内容、垃圾域本就不属于收录对象，不是"怕清单变杂"的问题。

**平台准入（判据①的定义）**：收"机构发布的信息载体"——**成体系载体与单篇技术文件同等收录**：论文、专利、白皮书、标准文件、厂商技术文档的单篇一律收，不得以"不是成体系入口""只有单篇没有入口"为由拒收。

- **机构** = 领域相关的厂商、标准组织、行业协会、研究机构、评测机构、开源项目官方渠道（官方社区知识库、开源邮件列表与缺陷追踪属机构渠道）；媒体平台、通用平台、个人、经销商不属于——新闻门户与资讯媒体一律不收
- **信息载体** = 文档、手册、知识库、标准、论文、专利、数据集、报告、白皮书、代码仓库等成体系内容或单篇技术文件；新闻、资讯、宣传稿、导购、评测晒单不属于

跨领域通用平台的首页/根域名无主题边界，不收——**主题边界看机构、不看页面**（知网首页与交换机无关，领域内厂商的官网不受此限）。**厂商官网首页 / 根域名（含语言首页）可收，且每个厂商必收一条**——厂商 = 做本领域产品与方案的公司与品牌（标准组织、评测机构、大学不适用本条）；确实找不到官网时如实记"未找到官网"（进未验证清单，不阻断收尾）。平台的领域专属入口（专利库的该领域分类检索页、标准平台的该领域检索页）可收；自身不提供领域内容、仅链接至其他页面的纯导流页不收；百科词条、问答、个人博客与论坛帖不收。垃圾域与低价值聚合平台（淘宝/知乎/CSDN 等大平台）由脚本名单（store.GARBAGE_DOMAINS）在入库时直接拒绝、收尾时过滤。通用平台对领域有价值的信息写入该领域条目的 `description` 传递（如"全国标准平台可检索"）。

**重复与替代关系（判据③的定义）**：

- **语义重复与替代（只收其一）**：同一 URL 内容重复出现；同一主题的合集入口与其包含的同一具体内容页同时出现时，优先收合集入口、不收该单篇；同一内容的多个语言版本按 **中文 > 英文 > 其他语言** 只收一个（判定依据：URL 语言特征 `/zh-cn`、`/zh/`、`cn` 子域、标题与内容语言；无中文版本则收英文版，仅有一个版本时照收，站点中文版内容不全时按实际存在的版本收）；同一内容的镜像或转载页只收其一，可识别原始页时优先原始页。
- **不构成重复**：同一机构、同一域名、同一产品线、同一体裁、同一节点内的不同独立内容均不构成重复（如同一厂商的官网首页与其文档门户是两个独立条目，互不替代）。
- **脚本去重机制**：record_sources 入库阶段 URL 原文完全相同（不截短、不去参数）的重复由脚本幂等跳过；收尾阶段脚本按"域名 + 名称"联合去重，**URL 剥离引用锚点后相同的一律判重**——同一入口被 record_sources 与 record_knowledge 各记一次、两次名称措辞不同时只留一条；同一域名的不同独立内容须使用不同名称收录（名称应如实使用资源名称，不得仅为规避去重而改名），同名同域会被去重移除；record_knowledge 同名重录为状态更新，收尾取末次。
- **重复无法确定时按不重复处理并收录**；内容级重复仅在可判断时按上述规则处理（脚本只保障 URL 原文级的幂等，不做内容级去重）。

**判断方式**：每次搜索返回的 N 条结果逐条过目、逐条判断——禁止因"整体印象"（如"都是同一来源的内容""都是转载页"）而对该批检索结果一次性放弃；提取为 0 的唯一前提是逐条判断后确实没有一条符合判据，禁止"没看到合集入口就放弃该批结果"。零提取时须在搜索日志 `zero_reason` 中写明拒收理由（已收/垃圾域/新闻资讯/个人内容/无主题边界等）。**"非成体系载体""只有单篇没有入口"不构成拒收理由**——零提取只能出自"结果整体与领域无关 / 命中垃圾域 / 已收录"三类情形。

**标注**：每条候选声明 `granularity`（合集级/单篇级，如实标注，脚本不拦截），单篇级在 `reason` 写明依据（如"单篇行业报告"）；`source_type` 是内容形态标签（如"厂商文档""市场研究报告""开源项目"），不填机构名、领域名或网址。**标"官网"的只限站点入口**（根域名 / 语言首页）——厂商站内的产品页、文档页、介绍页等按实际形态标注（文档 / 报告 / 数据库…），不标"官网"。

**提取率自查（非准入条件）**：结果集与领域相关的查询，10 条结果中机构信息载体通常占 2-4 条——其余为新闻资讯、转载聚合、垃圾域或已收录内容；整批结果确为低相关或非目标内容（书商、元器件站、SEO 聚合页）时如实提取 0，不得为提高数量收录。此标尺只触发逐条复核，不构成判据、不能覆盖收录判据；命中易失效词形导致结果集整体低相关时，本标尺不适用；已收录内容随运行推进增多时，不符合比例上升属正常，节点级提取率复核见阶段 4。

### 失败路径（搜索工具异常）

搜索大范围失败（多数查询无有效结果返回）时：停止搜索，**不调用 finalize、不产出交付物**，**向用户显式声明失败状态**（以一句"本次运行失败"开头，随后简述原因），不伪造候选，如实报告"搜索工具异常，本次运行中止"。已预留的运行目录保持为空残留。
