## 阶段 5 · 覆盖评估与扩量（含清单定案）

**薄弱判定**：每节点统计候选数与体裁分布，并按 6 个核心来源维度核对覆盖情况（官方组织与标准 / 厂商与产品生态 / 学术与研究 / 开源与社区 / 数据集与公共数据 / 行业协会与市场信息），按以下标准判定薄弱节点。候选数、提取数与**每节点体裁分布**从 **coverage()** 读取（`types` 字段由脚本从 store 算，不经代理自报）；来源维度是否单一由模型按判定表判断：

| 情形 | 判定 |
|------|------|
| 候选少（0 条或明显少于同级节点）+ 清单项有未验证 | **薄弱**——扩量轮优先把未验证清单项验证掉，而非无目标的泛搜 |
| 候选少 + 清单项全验证通过 | **不薄弱**——权威源就这些，强行扩充只会引入长尾噪声 |
| 体裁单一 | **薄弱**（补搜换体裁词） |
| 来源维度单一（条目明显集中于一个维度，如全是厂商文档） | **薄弱**——扩量轮按空缺维度定向补搜（用来源角色词构造查询）；根据节点搜索画像判断相关来源角色是否适用，空缺维度对该节点明显不适用时不补 |

**未验证项定案**（扩量轮内，每轮换一个角度：中英切换 / 全称缩写别名 / `机构名+官网/官方文档`）：

- 换角度重试后仍搜不到该机构存在的**任何证据** → 疑似幻觉/过时 → **从有效来源中剔除**，note="疑似无效机构"
- 能搜到该机构存在、但始终找不到官方入口 → 换角度重试 ≤2 次仍失败 → **留在未验证清单**，note="未找到官方入口"
- 只找到合集内单篇载体（note="仅找到单篇载体"）→ 换角度专找入口 ≤2 次仍找不到 → **以该单篇通过**（granularity 单篇级），reason 注明"仅找到单篇载体，未找到合集入口"
- 定案结果（剔除/留未验证/换角度后转验证通过）用 **record_knowledge 落库**（verified=false 项带 note；换角度后验证通过的项按阶段 3 字段齐套重录——同名重录即状态更新）

**终止条件**：所有节点**非薄弱或已收敛** **且** 两栏清单项（vendors + knowledge）全部了结（验证通过或已定案）。**扩量轮按节点独立判断，不再全局共享轮数**：仍薄弱且未收敛的节点继续扩量，非薄弱节点停止；某节点在一轮扩量中无任何新增有效来源时，该节点视为收敛并停止，如实报告。

**扩量轮内的搜索范围**：① 未验证项（两栏）换角度验证（每轮每项 1 次；含 note="仅找到单篇载体"的合集级项——它们的目标是找入口）；② 体裁单一的节点换体裁词补搜（每轮 ≤4 次）；③ 来源维度单一的节点按空缺维度补搜（每轮 ≤4 次，用来源角色词构造查询）。除这三类外不做其他补搜。

**谁执行**：扩量轮的搜索、提取与落库同样**整体下放子代理**（每 1 节点一组，派工模板见通用纪律"子代理派工"）；**定案与薄弱判定留主流程**——它是判断环节，依据是 `coverage()` 的条数与体裁分布。

**记录时机**：扩量轮每节点收敛后，把该节点补充条目与搜索记录按节点批量入库（同阶段 4 的两个批量调用）。**收尾前用 coverage() 自查**：missing 是粗略缺口信号（提取数含去重前与跨节点顺路发现、已收数是幂等去重后的入库数，两口径天然有差）——小额 missing 属正常，不触发补搜；只有当 missing 接近该节点一整批提取量时才怀疑漏调了 record_sources，补该节点。

- **阶段中途不与用户交互**：不产出状态汇报、不请用户选择方向（含"是否继续 / 是否缩小领域"）——本阶段做完即进入阶段 6
